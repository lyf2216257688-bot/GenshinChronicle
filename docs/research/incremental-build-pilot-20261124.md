# 跨版本增量构建的有限离线验证

2026-11-24。在现有已封存的 OBC、Clean 和索引资产上进行有限本地实测。样本索引和模拟变更独立保存。现用链与授权见 [当前阶段](../current-phase.md)。

## Dense

选择正式 Dense 的四个完整分片，含历史最长输入，共 512 行。保持 BGE-M3 权重、文本、查询编码和 FP16 CUDA 执行环境一致。先按原分片形状回放，再比较单条与固定形状双条。模拟每个分片替换一条资料后，与同输入全算对照。另对 511 条原文调换搭档、顺序及批尾。8 个工程问题在受控样本上各做微、宏两路 Top20。

| 方法 | 原始样本行/秒 | CUDA 保留峰值 | 相对旧向量超限 | 变化后未改文的超限行 | 旧 Top20 完全同序 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 历史动态批次 | 37.24 | 1194 MiB | 0/512 | 1/508 | 16/16 |
| 单条前向 | 27.00 | 1168 MiB | 304/512 | 0/508 | 11/16 |
| 固定形状双条 | 32.72 | 1212 MiB | 128/512 | 0/508 | 14/16 |

旧动态批次回放 512 条逐位相等。单条和固定双条在重新排列的 511 条均逐位相等，变化后以原数值复用的样本 Top20 均与同合同全算一致。本样本三个方法的 16 路旧 Top20 成员集合均一致。有限样本仍需在目标发布版上核对变化场景和正式查询编排。

以固定形状双条进入后续实现验证。试验使用 64、128、256、512、768、1024、1152 等填充长度，按实际未截断 token 数选择可容纳的形状，尾批复制自身填足两个槽位。超出现有观察长度的输入应先做目标合同和资源预检。工作点暂按旧向量零导入估算。在原 119,557 行中有 116,722 个不同的精确文本哈希，验证同键独立后，按每个实际数值键计算。只在存在绑定同一实际形状与运行合同的独立证据时才扩大导入集合。

按本次 32.72 行/秒和现有文本去重规模粗算，单套编码约 59 分钟。若候选版冷启动且再做独立全建，两套 GPU 前向约 119 分钟，另计模型启动、源验证、投影、索引写入与查询。此估算使用样本速度，目标语料清单封存后重算。

结果见 [Dense 报告](../../data/retrieval/incremental-study-dense-20261124-a2/report.json)。[可复现实验入口](../../scripts/retrieval/study_incremental_dense.py)

## BM25F

固定抽取 384 个 Clean 来源，得到 2,339 个共享候选。构造均匀和同栏目的 25 项变更，并加入 24 个用于测试 TopK 边界的同分候选。按原六字段和三个分析器独立全建两路 Whoosh 作为对照。活动桶的 reader 组合在同一个路由搜索器。分别核对两路活跃文档数、所有词的文档频率、字段长度总量和逻辑候选覆盖。

| 桶数 | 两场景重建时间 | 两场景重写 | 搜索器打开 | 热查询中位数 | 每路增加句柄 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 32 | 16.96–17.70 秒 | 68.48–69.57 MiB | 54–69 ms | 71–83 ms | 64 |
| 64 | 14.40–15.66 秒 | 51.34–56.74 MiB | 90–100 ms | 125–142 ms | 128 |
| 128 | 16.91–18.18 秒 | 35.74–41.56 MiB | 150–173 ms | 203–226 ms | 238–242 |
| 256 | 9.69–11.91 秒 | 21.72–22.38 MiB | 242–281 ms | 308–333 ms | 376–386 |

四档的统计和 Top20 均等价。封存索引复读检查每档 42,097 条查询命中，全部分数精确相同。热查询在复读阶段每路重复三轮。构建样本中 128 桶虽减少写入，两个场景耗时均高于 64 桶。256 桶写入最低，但热查询和句柄开销最高。采用每路 64 桶作为下一实施阶段工作点，整版验证再测真实更新规模、查询和磁盘开销。

结果见 [构建和 TopK 报告](../../data/retrieval/incremental-study-bm25f-20261124-a1/report.json) 与 [完整分数及热查询复验](../../data/retrieval/incremental-study-bm25f-20261124-audit/report.json)。[可复现实验入口](../../scripts/retrieval/study_incremental_bm25f.py)

## 证据回读与磁盘

- Raw 旧正式档案 16,437 条详情逐条校验，核对 99,619 个发现定位。夹具分别验证新增、修改、移除、未变化、频道覆盖待复核、正文未变而结构或归属变化、定位移动、部分或损坏归档拒绝。
- 夹具的 Clean 增量与独立全建得出相同逻辑 ID。第三版直接绑定第一版实际证据，完整独立回读也验证当前观测和有效历史观测。
- 分片夹具使用本地 tokenizer 对比增量与独立全建。相同资料直接引用旧文件范围，结构变化资料重新构建，零候选资料保留。后续统一输入对照通过，两种构建使用相同输入包 ID。同文不同来源拥有各自源标识，投影可同时读取当前与实际证据观测。
- Collector、Clean、Chunking 与索引回归集合共 219 项。Dense 运行环境通过 210 项，跳过的 9 项 Whoosh 用例在词法环境补验通过。对照报告的封存哈希、在用索引清单和两条正式 Clean 记录均已独立回读。
- 正式 Chunk 扁平导出登记了 16,437 个来源的范围。其中有 119,557 个候选、214,870 个父级、5,087 份图和 7,823,071 条准入记录。保留 460 个零候选资料。登记文件约 14.5 MiB，代表资料 `501157` 和 `509653` 已独立读取。同批未重跑正式分片。[来源范围目录](../../data/retrieval/incremental-chunk-baseline-20261124.json)
- 正式现有派生规模约 13.5 GiB。按两套同规模派生输出、新 Raw 和现有 6 GiB 余量粗算约 33.4 GiB。采集后按目标清单、可复用范围、索引实际写入、暂存以及两套输出的同时保留期再核算峰值。
