**建议继续维持 S0 默认，保留补充能力用于研究。下一步优先处理 Assembly 的预算/准入与模型选段覆盖，不继续调整融合权重，也不先增加 DeepSeek 动态 Sparse 路由。**

## 方案与控制变量

2. **U（候选补充）**：在同题固定 Macro/Micro Top50 窗口内，定义 Sparse 独有为 `Sparse IDs − (Dense IDs ∪ BM25F IDs)`；不能仅按“S0 最终100中没有”定义独有。保留完整 S0，再补入有精确缓存 BGE 分数的独有候选，不重新融合、不复制 S2 融合权重，不再截回100。
3. 全池统一复用选定 BGE-v2-m3/2048/不截断/结构整理/无 MMR 排序。原始 S0 候选值完全相等；两题中，排序后 S0 子序列的相对顺序也保持不变，但绝对名次会因新候选插入而后移。
4. **P（保护准入诊断）**：在 U 上固定“S0 BGE 前六回读＋所有已评分 Sparse 独有候选回读”，先保护同上下文/预算的 S0 Packet 已交付片段，再按联合 BGE 顺序尝试补充。若补充导致受保护片段或先前已接受补充丢失，则拒绝。最终输出仍按联合 BGE 顺序排列，保留全部处置和拒绝原因。

## 离线对照如何区分组包与完整请求

使用每题原 S0 初始研究上下文作为共同输入，不混入两边不同的模型研究笔记。三种回读策略独立记录：排序前6、前48诊断、S0前6＋Sparse 独有。
后者增加了12/11次回读，不能把其效果全部归因于融合。各场景均不超过既有48读取上限；前48仅为离线可达性诊断，不表示模型实际执行过这些读取。

- **固定 Assembly 对照**：初始准入60,000，输出保留8,192；最终准入196,608，输出保留4,096。全输入、处置和上下文均存档。这里的估算单位是保守 UTF-8 字节，不是厂商 tokenizer token。
- **完整请求对照**：固定输入实验的32个 Packet 中，有12个最终场景虽然通过 Assembly 估算，却未通过 Chat 请求封装预算；不能当作可发送的成功结果。
  随后仅重放 G5 现有的 `WHOLE_MESSAGE_BUDGET_EXCEEDED` → 准入上限每次减2,048 → 重新组包流程。请求总上限仍为196,608，没有扩大预算。
  实际准入上限和每一步结果均记录，最后32个场景全部通过现有请求 manifest 校验。
  该流程改变了各场景的有效准入上限，因此它与前面的固定预算 Assembly 实验分别报告。

P 在每次收缩后仍验证原 S0 Packet 的完整片段内容全部保留；不允许靠缩掉基线来假报保护成功。

## 主要瓶颈与建议

1. **检索**：确有 Sparse 独有剧情证据，保留 S0 的补充池能消除原权重变化和100候选挤出这一归因混杂；不能保证 BGE 前六或最终证据不变。
2. **回读/可见性**：Q050 BGE25的有效新证据不会被默认前六自动读到。扩大到48也不能保证入包。需要针对核心缺口选择已发现来源，不能用更多候选或读取数替代证据价值判断。
3. **Assembly/投影**：完整结构很昂贵，且模型消息再做 JSON 字符串封装会进一步增大 wire。Q046 的 `source_context` 与 `parent_context` 相等；大量逐段分支/字段元数据也占空间。值得研究保留全部限定/分支关系的无损共享表达，但本轮没有删字段、截原文或更换估算器。
4. **模型选段**：Q046 最终的决定性损失来自 select 将当前可见三段作为替代集合，排除已回读但初始不可见的身份/赠礼。当前来源/ID合法性校验不能证明该集合覆盖核心问题。应先研究“选择作为建议、对被排除的已知核心缺口显式复核”的小范围策略，不应直接无条件 union 所有片段。

P 比原 S2 更可解释，能证明有限增益，也能保护指定基线内容；它仍把一些非关键旧片段一并保护，挤占新增关键证据，尚不适合默认采用。
**本轮到此停止融合研究；推荐下一步聚焦选段替代语义、核心缺口覆盖与结构保真的预算准入。**
DeepSeek 按需选择 Sparse 暂后置：路由无法解决已经召回的证据仍未被送入最终 Packet。
