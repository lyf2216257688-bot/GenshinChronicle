## 复跑

从项目根目录在 PowerShell 7 执行。每轮选新输出目录，已有运行目录会被拒绝。

```powershell
$runtime = '.\.local\gte-reranker-runtime\Scripts\python.exe'
$env:PYTHONPATH = (Resolve-Path src)
$env:OPENBLAS_NUM_THREADS = '4'
& $runtime -u -m genshin_corpus.rag.embedding_70q --output 'data/retrieval/p04-embedding-70q-next'
```

运行会依次加载两套索引，避免同时在内存中保留两套状态。默认使用相同的
535,802 条 RU、Diagnostic C BM25、RRF (k=60)、Hybrid Top500、
本地 BGE v2-m3 Top500、0.35/0.65 排名融合、最终 Top20 和 Formal Deferred
Evidence Assembly。上下文预算 12,000 字符，每块 3,000 字符。
可通过 `--candidate-depth`、`--rrf-k`、`--rerank-depth`、`--final-top-n`、
`--hybrid-weight`、`--context-chars`、`--block-chars` 调整两侧共有参数。
每轮保留确切配置与输入散列。首次对照使用现有正式参数。

旧侧重放已验收的 70 条 2048 维查询向量，校验问题文本、顺序、请求身份与向量散列。
新侧用与默认入口相同的本地编码器逐条前向，复用一次模型加载。运行禁止网络连接，
只执行 `evidence_only`。两套全库向量、原 RU、旧历史问答和费用证据均作为只读输入。
程序每完成一题打印进度。长时间运行时应预留 GPU 和物理内存。

## 产物与评审

- `manifest.json` 保存输入、配置、运行身份和执行状态。只有 `complete` 且两侧
  各完成 70 题才表示成对执行完整。
- 每侧的 `Qnnn/rag_result.json` 及 `packet/evidence_packet.json` 保存 BM25、
  Dense、Hybrid、重排、组包诊断与最终原文来源。
- `paired-results.jsonl` 索引两侧逐题结果与散列，标记可见证据是否逐项相同。
  相同内容仍可能共同不足。
- `review/blinded-packets.jsonl` 是随机换侧后的问题、参考答案与最终可见证据。
  参考只在两侧检索完成后读入。复用 M2 的已审问题和历史盲评方式。
  完成判断后用 `review/unblinding.jsonl` 映射 A/B。
- 复制 `review/decisions-template.jsonl` 另存为评审稿。逐侧写
  `sufficient`、`partial`、`insufficient` 或 `pending`，在理由中列出支撑
  原文、遗漏要点和误导性证据，证据 ID 以 `A:E01`、`B:E01` 区分。
  成对判定采用 `a_better`、`b_better`、`equivalent`、`both_insufficient`；
  证据或参考含义不明时保留 `pending`。若参考答案和原文冲突，记下出处后待审。
  完成的行把 `status` 改为 `reviewed`，保留 `run_identity`。

```powershell
& $runtime -m genshin_corpus.rag.embedding_70q --output 'data/retrieval/p04-embedding-70q-next' --tally-review 'data/retrieval/p04-embedding-70q-next/review/decisions-reviewed.jsonl'
```

汇总器只校验人工或逐题评审写入的判定与证据 ID，再按盲评键统计。

质量统计须区分执行覆盖、文本相同、语义判断和人工确认。历史评审用于查证和
定位已知缺口，同题的新 Packet 需要重新阅读。仅候选命中、词面重合或引用
结构校验无法证明最终 Packet 足以作答。Generation 质量仍由独立试验负责。
