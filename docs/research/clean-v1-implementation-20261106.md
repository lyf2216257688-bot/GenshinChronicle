# Clean V1 实施与有限样本验收

日期为 2026-11-06。本工作按用户批准的技术方案完成基础实现与有限试点。
[Clean 合同](../phases/clean-v1.md) 负责持久化结构和接口，
[current-phase](../current-phase.md) 负责现状与采用边界。

## 1. 原则、调查事实与本轮决定

**用户原则**为 Raw 永久保留、Clean 直接依据 Raw 生成、保存全部实际内容和数值、
结构关系及原文定位。内容准入和分片策略交给后续环节。

**Luna 调查事实**沿用已有 16,437 条详情、84,072 个组件、30 种组件的结构盘点。
本轮以 inventory 和已保存的发现响应选择样本，读取 30 条详情开展验证。

**本轮独立设计与实施决定**为每记录 JSON、共享父级来源定位、整记录更新、
单写入者续跑、有限结构处理器和未知结构保留。
记录采用紧凑 JSON，阅读视图按需生成，避免深层缩进及重复定位链的体积开销。

对前期材料的校正保留如下。

- 《影域的遗留》的任务标签同时存在于详情 `ext.fe_ext` 与列表 `ext`。
- 46,765 个节点和 47,263 条边对应 `list[]` 分组。加入顶层结构后，
  调查附表可合计得到 5,087 组、60,682 个节点和 62,727 条边。
- `material_base_info` 同样用于成就资料，组件名保持结构含义。
- 当前 RU 代码按 1,200 字符连续分片，历史截断问题需要结合具体版本判断。
- 统计附表最终 `field_catalog` 有 415 项，其中组件字段为 150 项，
  部分早期计数字段与最终目录存在口径差异。

依据为 [结构调查](raw-data-structure-inventory-20261106.md)、
[统计附表](raw-data-structure-inventory-20261106.stats.json) 和本轮定向 Raw 核验。
前期调查原文保留其调查时点。

## 2. 实现内容

`src/genshin_corpus/clean/` 包含以下责任。

| 文件 | 责任 |
| --- | --- |
| `models.py` | 版本、TextValue、CleanRecord、CleanRef、筛选条件和保留数字字面的 JSON 解码 |
| `context.py` | 文件与来源池、记录内身份、资源关系和组件覆盖账目 |
| `markup.py` | 复用现有 HTML 解析基础，生成结构、文本范围、表格及媒体 |
| `field_rules.py` | 已调查组件字段形态，未知形态保留与诊断 |
| `obc.py` | 直接源适配、字段、条目组、对话、栏目及标签关联 |
| `pipeline.py` | Raw 校验、发现索引、输入绑定、锁、原子写入、续跑和命令行 |
| `reader.py` | 清单与记录校验、块筛选、文本迭代、来源解析、CleanRef 和导出 |
| `validation.py` | 独立 Raw 文本出现位置、表格和对话关系核对 |

复用既有布局观察、HTML 树解析、对话图诊断、严格 JSON 检查、原子写入和
操作系统文件锁。新代码与旧生产入口分别运行。

文件级校验和进入记录依赖。同一列表文件变化会影响引用该文件的观测，
这一粒度以来源可验证性为先。组件字段规则登记的是跨组件观测的形态集合，
具体内容含义仍由源位置及专门处理器承担。

## 4. 正式试点与独立核对

Raw 输入为 `data/raw/mihoyo_obc/zh-cn/p01eb_full_20260824/`。
正式试点位于 `data/clean/mihoyo_obc/zh-cn/clean-v1-pilot-20261106-r4/`。

- `metadata/manifest.json` 绑定全部选择、输入和记录校验和。
- `validation.json` 保存逐记录检查、源代码校验和及统计。
- `review/` 保存五条代表资料的纯文本阅读导出。
- `data/clean/pilot-selection-20261106.json` 保存来源已发现的选择集合及标题。

本轮试点构建约 **9.2 秒**，30 条记录均完成，覆盖全部 30 种观测组件。
该时间仅描述此本地有限样本。

| 核对对象 | 数量与结果 |
| --- | --- |
| 详情 | 30 条全部完成 |
| 组件 | 193 个全部计入 |
| 组件源值 | 6,907 个全部有处理去向 |
| 有内容的 HTML 文本节点 | 4,439 个，按源字段与节点位置逐一核对，出现次数一致 |
| JSON 表格 | 48 张 |
| HTML 表格 | 1 张 |
| 对话 | 5 组、39 个节点、41 条边，源载荷与 Clean 一致 |
| 源空组件 | 1 个，显式保存与诊断 |
| 来源及文本分段 | 全部定位链解析、校验和及分段回溯通过 |

独立核对直接从所选 Raw 解码源值、表格与对话。HTML 文本采用来源字段路径和
文本节点路径逐个比较，检查有内容的节点在主表示中恰好出现一次。
这一检查补充了构建器内部的源值去向账目。

定向检查包括阿蕾奇诺的 `50（27无武器）`、`5.0%`、材料数量、角色故事、
语音与命之座单列表格，《影域的遗留》的双来源标签与分支汇合，
`2283` 的顶层对话与空组件，成就页的材料组件，以及视频正文和资源引用。

## 5. 边界与后续

实现完成到基础能力与 30 条试点验收。全库材料化、分片方案、索引构建及
生产引用切换属于后续工作。现有 Parsed、Canonical、RU 与生产选择器继续
承担原有运行和历史引用责任。

媒体记录保存当前 Raw 提供的地址、标签及归属。完整 Raw 是恢复原 HTML、
未知载荷和精细出处所需的档案依赖。
技术验收确认来源、结构和内容保真，整体问答效果由后续链路评价。

本工作更新了 Clean 合同及拥有相关事实的仓库文档。
外部技术决策总账由用户的总账流程继续维护。
