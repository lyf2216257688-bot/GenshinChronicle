# F2统一语义评审与失败记录协议（执行前草案）

状态：仅协议及空模板；未见F2模型输出，未安排或冒称独立人工评审。
依据已确认v0.2五项原则，不重新定标G1-S1的48+2历史案例。

## 1. 权威、分母与材料

每条评审必须记评审者ID、日期、授权/同意记录及权威：
`INDEPENDENT_HUMAN_REVIEW`、`AGENT_REVIEW_NOT_HUMAN_GOLD`、
`SAME_MODEL_REVIEW_NOT_HUMAN_GOLD`、`PROGRAM_MECHANICAL_ONLY`。
人员/执行方式由用户决定，项目模型评审调用不在本轮授权内。
没有独立人工评审时，不报告真实语义准确率、人工金标准或“用户已认可”。

分母固定：16生成Pair每臂16请求；8审核Pair每臂8请求，内含4自然与4受控。
未发送、UNKNOWN、拒绝、截断、格式失败和证据不足分别保留，不仅统计成功返回。
F1-R2跨Pair复用和同题材依赖继续披露，不按24个IID样本计算总体准确率或置信区间。

所有实际原始模型文本及字段保留。旧版`proposed_claim`是安全表述字段，
原始输出中的`explanation`等可能包含其他断言；不能仅挑最好的一句作为“原始生成表现”。
新rc1的全部命题均保留，不取最高级覆盖Pair，不因多产命题提高通过率。
语义评审以命题及来源为单位，不因新版字段更多就判其语义更好。

## 2. 两遍评审与遮蔽边界

程序为Pair、实际命题及原句赋盲ID。映射只存未来run的`reviewer-private/blinding-map.json`。
本轮只交付模板，尚无实际输出可转换成盲化包。

第一遍只给实际命题原文、双端**交付子包**、实际覆盖、程序绑定alias/引文。
遮蔽臂名、模型、路由、Prompt版本、模型等级/verdict/release、风险层、探针类型、
构造理由及准备者预期问题。不让评审者预先阅读另一臂输出或完整母包。
以v0.2独立记录三轴、等级、发布建议、反例与不确定性，冻结第一遍意见及hash。

第二遍才解开原句、子命题、改写、发现和警戒的归属；核对是否保留原始实际判断。
需要判断“缺口是否必要”时可定向查母包，记录新增材料及阅读范围；
不能用母包事实倒推模型当时已见或把基于子包的合理保留边界判错。
最后对照原模型自评、另一臂及准备者探针记录，记录分歧而不覆盖第一遍意见。

输出长度、命题条数、措辞和字段习惯可能泄漏实验臂；自然原句也自带解释边界。
本协议只能降低确认偏差，不能称为严格独立双盲或认定训练记忆不存在。
F1-R2来源筛查提示本来就在两臂共同输入中，不能事后只对一臂去除以改善公平性。

## 3. 每个实际命题的统一评价

逐条回答并给可定位的依据：

1. 它具体断言了什么？“文献提出H”与“H为史实”是否混合？是否需拆分？
2. 双端支持属于明确、受限解释、弱、关键错误/无依据断言，还是必要材料不足？
3. 至少一个方向增加了什么具体理解？无/局部/实质/待定必须说明理由。
4. 是否把宽泛母题包装成文学对应？也反查是否因无互引而错拒具体文学联系。
5. 说话者、编者、小说、证词、二手考据及玩法目录的角色是否被越权？
6. 主体、人物身份、事件归属、因果与历史确定性是否有具体关键错误？
7. 必要缺口是什么？是否只是未读整页、关键词不命中或缺互引，而非真正必要证据？
8. 分别给v0.2等级与release，A/B不自动等于正式发布；零合格Navi是正常结果。

文学B沿用“解释性联读 / 非确定史实”。D必须指出具体错误，U必须说明必要缺口。
机械字段非空不证明增量真实，Schema PASS也不替代以上语义判断。

## 4. 原句、改写、新发现与探针

审核每个输入原句先记“是否被实际判断”。旧版若只给安全`proposed_claim`，
不能从正确改写推定原句已被正确拒绝。检查其完整解释后仍无原句判断，记`NOT_ASSESSED`。
程序不能仅凭旧字段名决定其语义结论；这一判断需带明确的评审权威。

rc1必须每原句恰有一条原text/role不变的判断；安全改写另项绑定原candidate_id，
新发现不占原生成信用，反事实警戒不是旧模型实际错误。
结构检查能证明文字保留，却不能证明判断正确。原句D不能被安全A/B改写洗白。

分别汇总：

| 分母 | 记录对象 |
|---|---|
| 生成原始输出 | 两臂全部实际断言、命题及失败；安全表达与解释中的过强断言同时保留 |
| 4自然审核原句/臂 | 原句是否被评、支持与增量、错误边界及评审权威 |
| 4受控探针/臂 | 错误归属、条件偷换、混合断言、必要省略各自识别情况；不计作生成模型既有错误 |
| 安全改写 | 原句实际结果、改写内容、删除断言及独立价值 |
| 新发现 | 是否有具体新增联系；归属审核发现，不冒称原生成发现 |
| 警戒 | 只作边界提示，不算模型原始错误或正式准入 |
| 技术失败 | 原生合同、公共解析、别名/范围/原句绑定及截断等分别报告 |

命题对齐由评审者说明文本及依据，不能用Embedding、关键词或最高等级自动认定同一联系。
没有人工金标准时，报告agent/model分歧、未决和UNKNOWN，不把定向争议比例叫总体错误率。

## 5. 定向复核：最多4对/8次

基础48次先全部封存，再按两臂风险信号的并集选最多4个生成Pair。
信号限关键身份/因果、必要缺口、混合命题或文学价值争议；触发者及权威留账。
超过4对按冻结命名空间`navi-v02-f2-targeted-1`、选样seed及Pair ID的SHA256顺序取前4。
每对两臂各1次，未选择/未执行项保留。不能按希望提升某臂评分挑选。

复核前另冻结实际原始候选注册表、文字hash、角色及原输出指针，剔除旧自评分、verdict和自检结论。
不能只挑安全改写，或遗漏原解释中的关键断言。rc1多原命题逐条保留；旧单命题限制作为接口差异记录。
仍使用同一F1-R2交付子包，禁止补母包后与原臂直接比较。新增材料实验需另立工单。
本轮8个复核槽位的Pair/候选内容为DEFERRED，不假装已有8个完整可发送请求。

评价复核前后每个相同命题、原句判断、改写/新发现、引入/纠正的问题及实际新增usage/费用。
格式失败不自动获得付费修复。可选8次必须另有明确调用授权；没有授权就保留争议停止。

## 6. 原始输出、失败与费用记录

未来正式根建议`data/retrieval/p05-navi-f2-<operator-run-id>/`，本轮不创建实际F2结果。
请求清单、输入版本、运行配置及授权先封存；每次有唯一request/attempt ID。
`attempts/<id>/request.bin`、原始response/分块、case与metadata先写，再做解码和验证。
每个状态事件用独立新文件；已存在attempt不覆盖，UNKNOWN不换ID重发。
raw在解码器或验证器崩溃时仍保存；字段失败的parsed对象可另存，不得替换原始字节。

每次记录Pair/臂/模式、Prompt/Schema/input hash、模型请求/返回身份、路由、参数、
起止时间、HTTP/传输状态、完整原请求/响应、usage原对象、计费映射、已知费用/UNKNOWN、
原生命题与自评、统一评价、定向父记录和授权引用。模板在preflight数据根。
当前适配仅支持非流式完整响应；若用户选择流式，需先补齐流事件/usage/完成性适配，不能直接运行。

状态至少区分：未发送、执行UNKNOWN、请求拒绝、上下文超限、输出参数拒绝、
输出截断、响应封装失败、JSON解析失败、旧原生合同失败、rc1 Schema失败、上下文合同失败、
模型身份不符/未核实、机械有效以及独立语义争议。有效U/零候选不是执行失败。

公共JSON层明确拒绝围栏、重复键和非有限数，不做修复；这项公共前置规则需与历史解析容忍度分开解释。
旧原生validator对额外字段的容忍度仍保留，模型多写的人工/发布字段只能作为原始数据，不能更改程序状态。
rc1额外字段由冻结Schema拒绝。两者合同差异不直接说明语义优劣。

自动/SDK/质量/格式重试均为0。UNKNOWN、未发送、请求配置/限额错误暂停批次核对；
内容格式失败按原计划留账，不单臂增加调用。手动重试或改参数需新授权/版本及预算，不能偷占可选8次。
48—56是设计上限，当前实际授权次数为0。

usage缺失为UNKNOWN，失败不假定免费；保留不确定请求费用占用。
缓存从输入总量中拆分后计费；已含在输出量的推理Token不重复加费；工具及其他费用独立。
未知价格、币种、舍入、推理或缓存政策时不声称获得严格金额上限。
程序状态保持`NOT_REVIEWED/INACTIVE`，任何语义建议均不能自动发布。
