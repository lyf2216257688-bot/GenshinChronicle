# Phase05 NaviRAG 首轮真实知识生成实验

日期：2026-10-29。代码基线为干净的 `main@ee0569e`；本轮未commit、push或切换生产索引。
用户明确授权小规模真实收费 Card、Link 生成和单独模型审核。本报告记录实际输出，
不设最低命中数，不把模型评分当成人工认可。

**结果：真实链路已执行，但本轮没有获得可列为有价值隐藏剧情新发现的合格关系。
当前结果的信息密度与阅读负担尚不足以支持扩大生成。** 主要暴露的是非剧情字段进入
Card/检索，以及原文交付预算被这些字段占满；不能据此证明 Navi 的隐藏联系方向无效，
也没有证据证明 Card 已带来有效剧情增益。

## 新关系与具体案例

**没有可以负责任列为“最有价值的几个新发现关系”的结果。** 六个有效生成结果共有
18条命题：C16、U2；剧情分类为NON_STORY12、LITERARY_ONLY4、UNKNOWN2，
CONCRETE_STORY与DISPUTED_STORY均为0。六个成功生成均未采用允许的零命题输出，
而把目录共性、否定判断或待查缺口列成命题，随后产生审核成本。

五个有效审核覆盖14条原句，均保持原句和角色；另一次审核失败。审核给出A4/B6/C3/U1，
但释放建议仍为EXCLUDED8、CATALOG_ONLY5、UNRESOLVED1，**正式剧情准入建议0**。
这些A/B多数是对“仅玩法/没有剧情联系”判断的高评分，不能统计为10条有用剧情关系。
本轮没有审核阶段NEW_DISCOVERY。审核为同一模型的另一次无原评分输入请求，
不是跨模型独立验证，更不是人工确认；人工接受数始终为0。

## Card相对RU检索的实际增量

每个Card查询均分别查询RU与Card索引，Top20、同一查询向量，保留各自命中类型、名次和
索引身份，再按既有RRF合并。统计为：RU覆盖66个来源对，Card覆盖60个；共有60个，
RU独有6个，**Card独有来源对0个**。12份资料总共也只有66种来源对，RU已经形成完整
候选对图，说明本轮设置下候选特异性很低；不是全库召回率或Embedding通用质量评估。

按“查询ID、发现方向、目标来源”计算，Card增加724条RU同查询Top20中没有的边。
但这些目标都已被其他RU查询发现，不能算724条新关系，也没有有效Link证明它们有增量。
例如：

- “波穗刃切与重锻/决定鬼人命运的真剑试合”查询：Card额外命中辰砂之纺锤；
  该对排第10，预算耗尽前未生成Link，不能判断存在剧情桥梁。
- “樱树下把酒对饮/那位神人”查询：Card额外命中幽夜华尔兹、曚云之月、浮浪记、鬼武道；
  这是语义邻近命中，当前没有双端证据支持的隐藏关系结果。
- “东山王与海兽夜游/巫女交往”查询：Card额外命中沉眠之庭、来歆余响，
  从现有原文与已运行案例看，不能将这种扩展直接当作有效线索。

两路查询都由Card生成，因此此对照仅观察**索引单位差异**，不能隔离“Card生成查询”
相对普通用户查询/原文查询的收益；检索范围也仅本次12份资料。没有证据声称普通全库
Dense找不到这些关系，亦不因本地Embedding历史指标稍低而否定方案。

## 质量、阅读负担与失败定位

1. **Card理解存在可用成分，但生产对象混杂。** 例如薙草故事Card保留“神人/昔日友人是否
   同一指称”的假说边界，波乱故事Card产生重锻、一心三作师承等具体查询。另一方面84批次
   中24批为成长数值、8批为秘境详情，另有大量装备展示、配装推荐与重复结构化表示。
   78个有效批次全部生成了查询，连数值字段也变成待查问题，信息密度不足。
2. **候选匹配缺少特异性。** 同类武器、突破材料、页面结构与主题大量投票；文档、章节和
   线索重复查询继续贡献RRF。完整66对候选图与首位无剧情关系案例是本轮实测事实。
3. **证据来源绑定正确不等于交付内容合适。** 八对合计交付127,475字符、遗漏318个已选
   摘录；多对把已经选中的“相关故事”全部挤出8,000字符预算。遗漏确有审计记录，但本次
   没有优先确保检索线索及双方故事上下文进入输入，是当前最直接的工程质量问题。
4. **Link生成与审核能保守排除，但低价值命题多。** 实际18条生成命题没有剧情准入项，
   仍消费6次审核147,935 Token；审核A/B分数与故事准入必须分开看。127,475字符还含重复
   表示与机制信息，人工逐对确认缺口的负担很大；这里不是估计人工分钟数。
5. **内容合同仍有实测失败。** 四次分别为Card阅读凭据遗漏、Link JSON语法错误、Link缺grade、
   审核C级命题的evidence_gap=null（要求string）。原件和失败用量保留，无内容重试。

没有发现本轮具体“引文绑到另一来源”的证据；来源与范围只读核验通过。
这不等于逐句语义理解、来源角色判断或未交付全篇均已人工验收。

## 实用性判断

**当前版本尚不足以直接扩大为实用的离线剧情发现器。** 本轮验证了真实传输、来源核验、
双索引、语义拒绝与审计链路，也实测了明确的噪声和交付问题。优先收敛非剧情投影、
重复投票与证据交付顺序，再在同等边界下验证；不需要先改冻结的剧情标准，也不应先扩库。

真实隐藏关系发现能力、Card带来的有效增量、全库检索效果及通用语义质量仍为UNKNOWN。
本轮没有为改善结果更换资料、改Prompt、补写失败响应或额外采样。新的付费实验、扩大
规模、生产采用与发布均留待用户决定；本次授权不变成长期自动生成许可。
