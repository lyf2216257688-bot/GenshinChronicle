## 前两份为何报告超过 11 万 Token

| 资料 | 正文字符 | 受控请求字符 | input | output | 其中 thinking | total | 驱动耗时秒 |
|---|---:|---:|---:|---:|---:|---:|---:|
| T01 天空之翼 | 453 | 5,200 | 32,053 | 29,842 | 26,569 | 61,895 | 229.211 |
| T02 林间风 | 1,891 | 9,237 | 22,951 | 31,169 | 24,070 | 54,120 | 310.806 |

合计 **116,015**；thinking **50,639**，是报告 output **61,011** 的约 **83.0%**。
thinking 是原生 usage 的单独字段，本表不额外叠加到 total，也不扣除 cache 字段。
两个终态用量均与各自 `agent_response` 步骤用量求和完全一致，不是本地恢复重复累加。

每份均有两步 agent_response、一次被拒绝的目录命令、三条 `streamGenerateContent` HTTP
日志。T01 尝试 `dir`，T02 尝试 `Get-ChildItem -Path .`；都被 `command(*)` 拒绝。
第一步分别报告 31,991 / 20,789 total，然后工具被拒绝，再继续生成最终 JSON。
工具拒绝限制访问，却没有从模型上下文中撤去工具或禁止提出调用，因此出现多步 Agent 开销。
原生系统/工具上下文也超出受控任务输入，不能将全部 input 归因于短篇原文。

准备目录的 `TASK.md` 有通用“不使用工具”说明，但实际 stdin 请求仅包含两边共同
Prompt 和交付材料；该文件没有额外注入，且读取文件工具被拒绝。不能假设模型已读该说明。
这为原生 Agent 探索倾向提供了解释，但没有原始上游完整请求，不能精确拆出每项系统开销。
三条 HTTP 记录不证明三笔均被收费；实际费用仍为 **UNKNOWN**。

**有不必要的 Agent 工具探索，不能把所有 High thinking 都判为浪费。**
本轮不降低 High 档、不删剧情要求、不改变五份受控请求，以保留对照条件。
后续成本优化应优先验证真正不暴露工具的单轮调用路径，或向两边共同增加纯文本任务执行说明，
另建公平版本；不要放开读盘权限来消除拒绝，也不要用降低阅读范围或深度代替工程优化。
现有资料尚不能证明某个原生 no-tools 开关能直接应用于已登录的 Gemini High 路由。
