## 5. Prompt/Schema审计的十项结果

| 检查项 | 已解决的结构问题 | 仍需什么证据 |
|---|---|---|
| 多强度命题 | propositions逐条支持/等级/资格，不用Pair最高分 | 模型实际是否合理拆分 |
| 原句/改写/新发现 | role五类，复用candidate_id/review_action；逐原句上下文核对 | 新发现是否真实有价值，安全改写是否改变了原意 |
| 直接/解释支持 | A要求EXPLICIT，B可具体解释并加标签 | 仅枚举不能证明文本确实支持 |
| 阅读增量 | A/B需至少一个方向的非空增量，reason另述正式价值 | 增量是不是泛泛包装 |
| 身份/因果/历史归属 | D错误说明与证据、U缺口、source_roles归属与边界 | 需要原文语义审核，不做自动真伪判断 |
| 评级/资格 | B可以不eligible；guard永不eligible；Pair无总等级 | 用户后续对具体产物的认可/发布 |
| 零合格Navi | 可零命题NO_FORMAL_NAVI；仅待审/缺证为UNRESOLVED | 模型是否愿意不凑关系 |
| 覆盖/失败/历史 | read/unread与交付集合核对；旧版本失败保留；原句hash固定 | read声明是否等于理解、缺口是否真的必要 |
| 精确证据 | 模型仅返回本端已读ID；额外引文/端点/哈希字段拒绝；提取与Canonical/RU核验仍由原owner完成 | 新样本真正构包时的精确绑定，本轮尚无新语料包 |
| 人工/发布状态 | 模型额外human_acceptance/navigation_status等字段拒绝，工具结果固定NOT_REVIEWED/INACTIVE | 用户未来授权；不能靠Schema产生 |

### 原缺陷的实际复现

用合成结构检查旧DRAFT：删除原句判断、只剩安全改写及新联系时，旧Schema仍接受。
rc1 Schema单独也不能知道外部注册表有几个原句；**Schema之后的上下文校验**实际拒绝：
`Every original needs exactly one unchanged assessment`。
因此报告不声称JSON Schema单独解决“洗白”；保存原句注册表、历史指针及追加结果是必要条件。
复现记录见`static-interface-audit.json`，合成对象见`synthetic-contract-fixture.json`。

原句的KEEP只表示保留该句的实际判断，A/B/C用KEEP、D用REJECT、U用UNRESOLVED；
它不代替release。SAFE_REPHRASING用REWRITE并另列原句；NEW_DISCOVERY用PROPOSE且不冒认旧candidate_id；
guard用PROPOSE但只能排除/未解决。模型与程序的所有历史记录都不原地更新。

## 8. 反向审计

- **文学错杀**：不要求互引、同名或作者意图；S19/S35的规则方向保留。具体对应/增量是语义条件，
  不把关键词数量硬编码。S04/S34仍可待审，不为提高B比例放宽。
- **普通相似放行**：B标签不充分，release另审；合成B待审、目录、排除路径均可工作。
  程序检查非空增量不能识别漂亮空话，必须在新样本中专门看误准入。
- **引用与史实**：EXPLICIT只支持命题本身。文献确有假说不证明假说为真；D/U条款保留明确错误与缺口差别。
- **评级洗白**：原句完整账本与改写分开，实测去掉原句会失败；新发现可独立成为候选而不追认原句。
  警戒项既不入候选，也不充当原生成错误数。
- **来源偏见**：二手/游戏小说/编辑栏目不作机械降级；要求段落依据和解释边界，不宣称二手一致即独立证词。
- **并行Embedding影响**：仅在当前工作树编辑指定规范、新离线检查器/测试与独立准备根；
  没有调用其脚本、改索引/依赖、访问其他工作树内容或终止进程。无需借其新成果完成本任务。
- **确认偏差**：八例与48+2已校准，不能再作独立性能证明；排除范围扩到1042旧来源。
  新样本仍需检查相邻故事和近重复，不能把ID不重合直接称无泄漏。
