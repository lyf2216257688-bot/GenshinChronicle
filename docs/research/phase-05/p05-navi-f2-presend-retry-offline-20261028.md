# F2 Responses 发送前失败有限重试：离线适配

**状态：离线验证通过；正式续跑未授权、未执行。** 本轮没有新的模型请求、付费调用或连接探测。已停止的两份历史运行和48槽账目保持不变。

## 已复用与最小适配

`navi_r1_experiment.py` 的 `qwen_traced()` 将每次连接尝试单独留证，只在可证明发送请求头前的TCP/TLS连接失败时最多尝试三次，并在尝试间等待0.5秒。F2的 `navi_f2_sdk_transport.pre_send_failure()` 已实现相同的轨迹判据，`navi_v02_call_recovery.run_one()` 已实现一次Responses调用、原始HTTP响应/SDK事件及trace留证。由于Qwen函数绑定了其自身Chat Completions/embedding及账目接口，不能直接拿来发送F2 Responses；本次在现有F2续跑入口内复用上述判据、单次调用及留证，未新建通用重试框架，SDK和底层传输自动重试仍为0。

F2对已有判据再加严格约束：任何请求头、请求体或响应事件均禁止重试；必须有一致的 `NOT_SENT` 状态、无HTTP响应/SDK事件、冻结请求和本地实际请求正文一致、reservation/route/retry配置一致，且各文件哈希相符。缺失、冲突或校验异常均停止。只有通过这些检查，且未达到每槽三次尝试上限，才可以在同一进程继续下一次尝试；未知执行状态、截断、协议问题、校验器异常或异常usage均不重发。完整可信响应的JSON/Schema/内容合同失败保留为失败，直接进入下一槽，不修补输出。

每个新尝试拥有独立 `attempt-NNN` 目录，保留请求、reservation、trace、原始响应/SDK事件（如有）、结果、校验和带哈希的重试决定。若进程中断，已有新运行根阻止自动恢复，防止未决尝试被重发。该记录与旧根分离，账单或费用无法确认时保留 `UNKNOWN`。

## 第3槽与历史保护

此前第3槽记录TCP连接成功后TLS握手失败，未观察到请求头发送；该历史记录通过原审计和完整文件哈希复核。它计入三次上限的**第1次**；未来若另获正式授权，最多可有第2和第3次尝试。第1、2槽不进入新派发顺序；第4–48槽从各自第1次开始。正式请求顺序、两臂、冻结Prompt/Schema/资料、Responses单user消息、JSON object和30000输出上限不变。

启动前除原48槽计划重建和前两槽原流重放外，还核验历史续跑审计的SHA-256、9个文件的完整集合与哈希、停点、48槽状态以及第3槽trace/请求指纹。新运行目录采用create-only；无授权时默认只执行本地 `DRY_RUN`。本轮没有创建新运行目录。

- 本地SDK/HTTP MockTransport 模拟TCP/TLS发送前失败和已经出现请求头发送事件后的失败；前者可由trace证明，后者保持UNKNOWN且不重试，没有使用真实网络。
- 离线模拟验证第3槽历史尝试计数、两次新尝试上限、独立尝试目录/哈希、穷尽后停止、UNKNOWN不重试、内容合同失败后继续、协议错误/校验器异常停止，以及历史哈希篡改拒绝。
- 既有原运行22文件及续跑9文件逐项哈希和文件集合均与各自审计一致。
