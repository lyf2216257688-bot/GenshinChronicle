## 1. 要回答的问题与规模

建议24个全新Pair，分为**16个生成样本、8个审核样本**；每个Pair的两端均为新来源，
不同Pair不共享来源。它是发现合同/语义风险的小型诊断，不具备总体准确率或全库外推能力。
不重建Card，不测全库发现召回，不改生产检索，先控制B阶段输入一致性。

| 风险/文本形态层 | 生成 | 审核 | 取样线索，不是预期等级 |
|---|---:|---:|---|
| 明确剧情引用/改编 | 2 | 1 | 来源实际出现作品名、引用或改编讨论 |
| 事件/特殊机制补充 | 2 | 1 | 原文有可对照的特定事件或机制细节 |
| 无直接互引的文学结构 | 2 | 1 | 具体物件、场景、叙事转折可比较；价值尚未判定 |
| 宽泛主题邻近 | 2 | 1 | 共同常见主题，未见独特桥接；允许后来发现意外高价值联系 |
| 目录/同源版本 | 2 | 1 | 栏目或版本相近，不能预设无剧情增量 |
| 二手/原叙事混合 | 2 | 1 | 有明确二手标记与可核对原叙事 |
| 身份/主体/因果归属风险 | 2 | 1 | 多角色、转述、条件与归属易混，不预断已错误 |
| 必要证据/覆盖风险 | 2 | 1 | 自然缺口或预登记的受控省略，不能把任意截断判U |
| 合计 | **16** | **8** | 8种形态各3对，无A/B配额 |

每层2个生成样本用于观察重复风险，另1个审核样本使审核评价不只依赖两种生成Prompt各自
挑出的候选。它不是统计功效计算所得的精度保证；若某层找不到新材料，报告PARTIAL覆盖缺口，
不能借已校准案例补位。

这比只排除48+2个Pair更严格，亦覆盖该表承接的R1/R1-QA材料。**清单不是新样本清单**。

未来取样步骤：

   不采用并行Embedding任务未审定的索引或环境。若用既有检索，两个实验臂共用冻结结果。
2. 从候选池剔除清单内来源ID、Canonical哈希，以及已知旧校准Pair；
   查证R1十例/用户另行讨论资料是否有不在1042表中的补充排除项。发现则在抽样前追加版本，不能静默漏掉。
3. 对候选正文检查精确段落哈希，人工定向排查近重复版本、同一剧情链的相邻章、
   改名重发或直接复述校准事件。记录排除原因及定位；仅做有限取样去重，不建设全局实体/别名系统。
4. 选择人员只读来源作形态分层，不读新模型输出、不写期望等级；同一Pair可多标签，
   主层按上表从上到下的先后归入第一个适用层。所有候选/标签/排除项留账。
5. 用户在看模型结果前固定seed（建议初始值`navi-v02-fresh-1`，可自行选定）；
   Pair方向按源ID字符串排序后固定。层内按
   `SHA256(seed + "|" + canonical_hash_A + "|" + canonical_hash_B)`排序，依次取互不共享来源的3对。
   每层前2对归生成、第三对归审核。排重跳过也留记录，不能看结果后换对。
6. 冻结24对、48来源、来源家族检查、章节/片段、取样风险标签、覆盖缺口、方向、别名映射、

这里的“独立”指上述旧来源、证据和校准故事去重，不能证明模型训练记忆从未见过该材料。
若后来发现泄漏，保留结果并单列contaminated disposition；替补仅在调用前允许，调用后不偷偷换分母。

## 3. 输入准备、生成样本与审核样本

### 3.1 共用证据包

沿G1已验证的Canonical/RU交付方式离线构包，按真实章节组织，保留来源角色、说话者、
否定、条件和实际遗漏范围。程序提取精确引文，模型只用本端alias；不能为了Token目标
破坏关键上下文。两个臂收到同一原文、方向与覆盖，禁止给一个臂补证后作直接性能比较。

覆盖风险层优先用自然缺口；若用受控省略，提前固定完整母包与删去的关键段，
两臂均只见相同子包。评审者可以看完整母包以判断“缺口是否必要”，模型不能偷看。
完整母包仍不足时只能标UNKNOWN，不能制造判定依据。

### 3.2 生成16对

- **旧臂**：冻结当前G1实现的有效`PROMPTS['link']`完整模板和v0.1单命题合同，
  不使用历史已修复的追加字段版本，避免拿已知格式缺陷作弱基线。
- **新臂**：冻结rc1生成Prompt、完整模板、Schema与离线检查器版本。
- 同一用户选定模型/路由、采样参数及输入；配对调用顺序在执行前随机并留账。
  两臂各16次，共32次。模型配置不得跨臂变化，否则另列混杂因素。
- 原始输出、结构失败、原命题与新臂每个命题都保存；不能只留最好的安全表述。

### 3.3 审核8对

审核不只检查上述两臂生成物：使用另外8对新来源建立独立冻结候选注册表。
每包1–2个原命题，字段为id/text/role/text_sha256/来源定位/构造来源；不附期望等级。
其中4包为选样者基于原文形成的自然候选，4包为**明确标注的受控探针**：
错误归属、条件偷换、混合命题和必要证据省略各一类。构造过程、改动前后文字和依据只向评审开放。
预先对应为：事件/机制层用条件探针、二手混合层用混合命题探针、身份归属层用错误归属探针、
覆盖风险层用省略探针；其余四层用自然候选。若来源不支持预定构造则记录覆盖缺口，不强写错误。
受控探针不是真实模型犯错，不与自然候选混算错误率；本轮尚未编写这些实际命题。

旧/新审核Prompt各看同一8包，共16次。新臂必须保留原句判断，再另列安全改写、新发现与警戒。
旧臂按其原生接口评价；它没有rc1多命题字段属于**接口能力差异**，不能直接算模型格式失败。
旧臂只返回安全改写而没评原句时，原句结果记`NOT_ASSESSED`，不能从改写猜出它已正确拒绝原句。

## 4. 比较与评价

先固定输出、请求及失败账目，再去除臂名和自评分，将命题+双端证据随机编号供独立审核。
风格、条数与接口仍可能泄漏实验臂，记录盲化限制，不宣称严格盲审。

旧v0.1评级只作历史/程序投影对照；两臂语义内容统一依据已确认v0.2评估。
同一Pair可以产生不同数量的命题：保留全部，以原命题、相同联系、安全改写、新发现分别对齐；
不取最高级，不以多生成增加通过率。相同联系对齐本身是语义判断，不能靠相似度冒充证明。

| 评价维度 | 记录与分母 |
|---|---|
| 证据支持 | 每个实际输出命题的支持轴、双端定位、条件/否定保留；无法判断单列 |
| 实际增量/剧情价值 | 记录具体新增理解、无/局部/实质/待定的理由；按命题发布建议另报，不用A/B比例替代 |
| 主体/身份/因果/历史断言 | 指出具体错误与原文依据；只统计模型实际原句，改写与警戒分开 |
| 文学误准入/误拒绝 | 由独立语义评审逐例定标并说明边界；没有独立认可时只报分歧与UNKNOWN，不能报真实错误率 |
| 原始错误洗白 | 原句是否有不变文本的判断、改写是否独立、NEW_DISCOVERY是否冒认原发现 |
| 格式/机械 | 每臂按原生合同报请求级有效数、别名/端点/覆盖错误；不把字段合同差异当模型能力提升 |
| 零候选能力 | 无eligible、仅待审、缺证的分母和Pair状态是否正确；零候选不是失败 |
| 复核增量 | 同一实际命题复核前后支持/资格、纠正或新引入的问题、额外已知用量与失败；不只看等级变化 |

若用户安排独立人工评审，先记录其明确授权、角色与逐命题意见；用户确认五项原则不等于
认可新样本。若只有agent自审或同模型复核，结果权威仍为AGENT/MODEL_REVIEW_NOT_HUMAN_GOLD，
只能说明合同执行和agent/model分歧，不能证明语义准确率。
本轮已校准的48+2对只作回归，绝不并入新样本性能分母。

## 5. 定向复核与调用上限

基础为32次生成+16次独立审核包调用=**48次**。可选定向复核最多8次：
从16个生成Pair中，按两臂输出合并后的风险信号选择最多4对，每对的两个臂各1次，
以避免只给某一臂额外纠错机会。信号包括关键归属/因果冲突、必要缺口、命题混合或文学价值争议；
超过4对时以冻结seed排序，不按期望改分挑选。所有触发与未复核项留账，格式失败不自动付费修复。

合计建议**最多56次**，这是计划边界，不是本轮执行授权。若用户只批准基础48次，则记录剩余争议。
不默认全体第二次完整审核，不自动重试UNKNOWN、切模型或重发；遵循未来工单明确的失败政策。
原始请求、响应、usage、失败、UNKNOWN及未完成分母都保留；不能成功后抹除失败。

## 6. 成本估算依据与预算闸门

本轮实际新增项目费用为0。未来费用依用户所选接口计价，未选模型/价格，不能给实付金额。
先离线构包后用所选tokenizer计数（不调用计费接口）；未确定tokenizer前，只能使用假设范围。
以**每次输入8,000 Token、典型输出1,600、输出上限3,200**作透明规划例：

| 请求范围 | 输入规划量 | 典型输出 | 输出上限预留 |
|---|---:|---:|---:|
| 基础48次 | 384,000 | 76,800 | 153,600 |
| 含定向最多56次 | 448,000 | 89,600 | 179,200 |

输入8,000是规划均值，不是允许删证据的截断阈值。构包后若超出预算，先调整计划并由用户决定，
不能无声裁掉关键章节。输出达到上限而不完整计为失败，不将截断内容修成有效JSON。

若输入/输出价格分别为每百万Token的`P_in/P_out`：
基础典型量约`0.384*P_in + 0.0768*P_out`；56次典型约`0.448*P_in + 0.0896*P_out`。
输出上限预留则分别把输出系数改为`0.1536/0.1792`。
缓存/推理Token/工具费按所选接口另加，不预设折扣或隐藏推理免费；UNKNOWN保留预算占用直到能核实。
不需要新云Embedding调用；如未来改变为含检索比较的实验，应另立预算与授权，不追加到本方案里。

## 7. 执行前、执行后与停止条件

**用户执行前需决定**：工作位置和输入快照、候选发现方式、模型/路由与调用协议、tokenizer、
采样参数/输出上限、seed、是否采用24对与可选8次复核、单次及总费用上限、独立评审安排和后续工单。
这些是运行选择，不能用旧G1授权代替；五项语义原则不需再审批。

执行顺序：冻结上述选择与排除清单 → 离线候选池/分层/去重并冻结24对 → 精确构包与机械检查
→ 冻结两臂Prompt/合同 → 用户授权调用 → 保存48次基础结果 → 统一语义评估
→ 按预算做至多8次定向复核 → 汇报全部分母、失败、争议、已知用量与UNKNOWN → 停止。

任一输入哈希不符、校准泄漏未处置、关键证据绑定失败或授权/预算不明，停止该受影响步骤并保留记录。
文学/增量的语义争议不制造PASS；零候选也不能引发无限扩样。
结果最多支持进一步试验建议，不自动ACTIVE、不改变人工认可、不推广全库。
