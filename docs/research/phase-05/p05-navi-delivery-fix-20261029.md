**结论：双方完整故事已真实进入请求，交付修复成立；复测得到一条模型B级争议解释，

## 原因与修复

旧运行来源对 `142ee444d55c95b3336478e678d2bb0e659f47575393e8b9ae94ebabe4316471`
已经选中两端故事。但交付代码把各次发现的引证按字典插入顺序装入每端8,000字符预算，
没有叙事优先级；结构化数值表等先进入，后来的故事即使很短也被记为遗漏。
Canonical/RU绑定没有错，错误发生在**交付选择与有限预算分配**。

在既有 `navi_offline/pipeline.py` 增加 `select_link_evidence`，并替换原流水线中该段装包：

- 依据来源的真实章节标签、RU种类安排阅读顺序：故事/剧情/语音等正文及对话优先；
  小说、圣遗物等无固定故事标签的可读正文仍保留。标签仅是阅读提示，不认证其为史实。
- 从已经验证的双方RU目录补取正文与上下文，避免仅因命中的是数值字段就永远读不到故事。
  优先保留发现的正文片段，再补同单元及其他正文；输出仍按Canonical顺序展示。
- 总上限保持每端8,000字符。描述、结构化伴随表示、数值和配装等共享**至多512字符**
  的辅助预算，不能填满剩余预算挤占剧情。没有武器名或来源ID特判。
- 引证仍由 `Sources.quote/verify_quote` 精确产生，保留RU、Canonical、原定位、角色和分支
  结构。不同定位的相同文字不合并；结构化伴随表示不被宣告等同于正文。
- 长正文必要时仅提取精确前缀，记录交付和未交付范围；预算不足的对话片段整段延期，
  不把分支图截成伪完整对话。两端无可安全交付片段时拒绝派发并保留交付审计。
- 审计逐RU记录类别、优先级、完整/部分/遗漏、范围与原因；请求包含章节交付统计、
  片段实际范围及非全页覆盖声明。未交付内容没有阅读alias，不会进入有效read_ids。

Card Prompt、冻结v0.3 Prompt/Schema、Embedding模型与索引、候选发现与RRF排序均未改。
这是一项下游证据交付策略，未改Raw、Canonical或既有RU投影。

## 真实复测结果与原文核对

复用 `jizhi/deepseek-v4.1-flash`、Responses流、`json_object`，生成和审核输出上限均维持
30,000 Token。新交付形成新请求指纹，使用原持久账本；两次均HTTP 200、完整流/usage/
JSON/Schema/上下文合同通过，没有失败或重试。

生成4条命题：p1为B / DISPUTED_STORY / REVIEW_REQUIRED；p2为C / UNKNOWN / UNRESOLVED；
p3为C / LITERARY_ONLY / EXCLUDED；p4为C / NON_STORY / CATALOG_ONLY。
审核原句和角色保持不变：p1仍待查，p2转文学对照并排除，p3仍排除，p4仍目录项。
**审核最终为待审1、排除2、目录1；ELIGIBLE_PENDING_RELEASE为0。**

- **模型提出的背景联系**：A端巫女保护出航者、解结界让紫电之鸢怨恨袭击雷神旗号舰船；
  B端曚云随海祇出征，出现双子、东山王、海兽与灭亡叙事。模型将其组织成“海祇—幕府
  冲突背景”的争议联读，并明确不能证明同一巫女、同一把弓或同一事件。独立审核保留B。
- **Agent原文核对：不能确认上述共同阵营。** A端明确的是清籁、赤穗百目鬼、左卫门、
  影向山、雷神旗号；并未明说该巫女属于海祇。将A端也纳入海祇势力，仍超出已交付
  文本直接支持。该B建议不能展示为已验证的共同历史。
- **生成和审核共同出现了归属错误。** p3的增量说明将“随将军出征”归到左卫门。
  原句却是“如果当初教我射术的人没有随将军出征的话，那我们的儿子，如今应当是
  左卫门的年纪了”。这不能证明左卫门是随将军出征者。审核没有纠正这一错误，说明
  原文完整送达和原句审核通过，都不保证模型真正理解人物指代。
- **阅读声明也有误报。** 生成模型声称A端“装备故事后段”未交付；程序逐字核对显示
  332字rich_text完整送达，未交付的是另一个结构化表示等RU，不是该正文后段。
  审核使用了“整页未覆盖”的较准确限定，但不能据其read_ids声明认证阅读理解。
