本轮执行了用户授权的 **5 次 Metro 请求、零重试**。没有新增 Gemini 调用，没有再生成
Gemini T03，没有更改生成 Prompt、Schema、来源标准、模型选择或输出预算。
现有独立盲测的五份实际交付原文及范围保持不变。
所有产物 `INACTIVE / NOT_REVIEWED`；本轮只准备匿名语义审阅，不判定模型胜负。

## UNKNOWN 后的有限授权

首次直接执行已有 `Run-DeepSeek.ps1`。T01 的 HTTP524 / UNKNOWN 用量触发原有停止保护。
用户随后明确回答“允许继续剩余4份，保留T01用量UNKNOWN”。

程序追加 `deepseek-independent-dispatch.json`，绑定原 T01 完成哈希、原准备哈希、实际代码
身份、T02–T05 四个允许的新资料和总共最多 5 次的边界。
接续使用同一流水线的 `--independent-unknown-authorized` 显式入口，不改变实际请求内容。
该例外保留 UNKNOWN，不把未知计数写成零，不更改通用默认保护，也不允许重发失败指纹。
累计 Token 无法被完整核实；本次按用户授权的固定五份/五次发送边界运行。
授权次数现已全部用完，后续恢复检查只能复用已有原件。

`runtime-revision-0003/` 追加封存这次导出/有限调度代码，绑定前两次快照及全部原有完成
记录。旧 prepared、Gemini 原件/恢复、DeepSeek T01 原件、指纹和账本均不改写。

映射只在控制根的私有文件中，**不在评审包里**；不要在独立语义审阅前揭晓。
包内不包含模型名称、调用日志、Token、耗时、历史答案、复核报告或账本。
失败原因使用通用类别，避免原生错误中泄露模型名称和接口信息。

有效一方包含全部归一化语义字段、程序确定的引文范围、阅读覆盖、限制及现有版本的
剧情向量投影文本；未重新 Embedding。来源 ID 从短别名恢复为真实证据身份，补充了
程序范围，因此共享 `card.schema.json` 是原模型响应的 Schema，而非归一化 JSON 的重新验收声明。
双方相同的交付原文、证据映射、阅读计划、语义 Prompt 和空白 rubric 同包提供。
失败一方只有机械状态及原因，没有伪造 Card；semantic_score 为 null，不能按零分统计。

仅 **T02，1/5 文档** 可完整配对；3/5 单方有效，1/5 双方失败。
整体机械通过率为 Gemini **4/5（80%）**、本轮指定 DeepSeek 路由 **1/5（20%）**。
这包含渠道、身份、截断及来源合同失败，不能直接解释为模型的内在语义能力差异。
报告完整语义比较时必须同时报告这一覆盖率，不能只展示成功子集来外推整体质量。
