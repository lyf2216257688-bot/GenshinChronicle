## 结论

**G6 接入工程通过；本轮没有证明 S2 改善最终问答，常规配对出现了明确退化。建议维持 S0 默认，保留 Sparse/S2 为待研究能力。**
最终是否采用 S2 由用户决定。没有改动冻结融合参数、重建上游、增加 DeepSeek 动态路由或切换默认入口。

工程验收、来源/引用完整性与语义质量分别判断。HTTP200、BGE 高分、更多 Chunk、合法引用和模型自称 sufficient 都不是回答正确的证明。

## 典型原文与下游去向

### Q046：有效新增与关键证据损失同时发生

题目：“迪奥娜无论如何调酒都容易变得好喝，这份祝福来自哪位纯水精灵？”

Sparse 独有 row63311（Chunk `59a91c8f…`）仅 Sparse micro42 命中，S2召回100→BGE4：

> 卡莉露：我给予你的赠礼，同样会陪伴着你长大。
> 重云：（难道说，迪奥娜调出美味饮料的体质，是这位精灵祝福的结果吗？）

这是有效的直接剧情联系；重云的疑问句仍是角色推想，不能抹掉其语气升格为全知事实。
它进入196K离线诊断 Packet，却在真实60K初始 Packet 中 `budget_excluded`，最终被模型选段排为 `not_selected`，没有被最终回答使用。

S0 已有 row63315（Chunk `03211842…`），S0召回83/BGE3；S2仍保留同ID，召回98/BGE6，原文明确：

> 卡莉露：不…抱歉瞒了大家这么久…我其实，是一只很久以前从枫丹流落至此的纯水精灵…

后文还有她在清泉镇定居的叙述。**不能把新增赠礼 Chunk 说成 S0 原本完全没有卡莉露姓名或纯水精灵身份。**

两边初始 Packet 都排除了这段长对话；S0 控制器只 finish，最终完整预算将其重新纳入（E03），答出“卡莉露”。
S2 控制器 select＋finish，仅选择三个当前可见片段，最终 `not_selected` 同时排除了旧身份对话和新赠礼对话；答案只给“泉水精灵”，并称现有原文未给名字。

这是本轮明确的最终回答退化。丢失发生在组包/选择，不是候选根本没找到：新增高排位片段、相对排序、初始预算和模型选择共同改变了输入。
单次样本没有隔离模型随机性，不能推出“Sparse 必然导致退化”或把全部责任归于某一个融合权重。

### Q050：确有新姓名证据，但没有进入自然可见范围

题目：“雷穆利亚时期的四位大调律师分别是谁？”

Sparse 独有 row16380《香韵奏者》（Sparse macro30，S2召回98→BGE27）：

> 仁善的大调律师优恩尼娅静心倾听旧日之人的进言，为他们的恳求陷入深思。

这是固定 S0 窗口未覆盖的有效“名字＋称谓”原文。前六候选诊断 `not_selected`，全回读诊断 `budget_excluded`；
本轮没有通过调权重、扩大前六读取或改变预算把它强行补入答案。

Sparse 另将两段《谐律上的咏叙诗》对话排到 BGE1/2，补充波爱修斯/卡西奥多的相遇、共同侍奉神王等文本。
它们不自动证明两人及另外两人组成完整四人名单。旧共享证据也会后移：奥里略斯碑铭召回26→14，但 BGE26→32，未到前六/诊断 Packet；
塔耶芙尔对波爱修斯的直接台词，召回改善也没有变成最终优先证据。

常规 S0 控制器提出两次针对名单缺口的补检，首个本地查询触发可用 RAM 保护；该已封存模型控制请求未重发，保留中断记录，不把资源故障算作 S0 质量退化。
随后用原始排序前六读取、相同最终预算/模型，做 final-only Packet 对照，单独检验生成；这不是完成了同条件的常规自主研究配对。

固定 Packet 的 S0 回答只确认波爱修斯和“四位”建制，明确无法给出完整名单。
S2 原操作恢复后，使用新增 row58774 中波爱修斯自称“「福波斯」的首席调律师”的直接台词，并增加了卡西奥多；新增 row58797 确实带来“你我共同侍奉至尊的神王”的原句和小呜斯/卡西奥多的联系，说明 Sparse 独有对话已经影响回答，波爱修斯的身份也得到更直接的对话支持。
但“曾共同侍奉神王”不直接等于“四位大调律师之一”，当前 Packet 没有将卡西奥多明确列为该四人之一；模型最后的“已确认两位”超出了所列依据的直接支持，应保留为候选线索，不能判作可靠补全。
此外，S2 原答案使用“（E03）”等括号形式，缺少程序规定的“[E03]”；实际可渲染引用列表为空。恢复助手的通用引用校验对空集合返回 PASS，不代表此答案已经满足最终回答的引用要求；本次审阅将其标为引用格式未通过，原文和旧回执不改写。
两边均未列全四人；真正明确称作“大调律师优恩尼娅”的 Sparse 新原文仍未入包。因此结论是“新增有效线索影响了文本，但没有得到可接受的完整答案”，而非 S2 整题改善。该配对是相同最终预算/首六读取的独立诊断，不冒充 Q050 的常规自主研究验收。
两份已知最终调用分别报告输入/输出32,797/208（S0）和50,593/268（S2）token；S2 原操作恢复时已进入官方高峰计价时段。更长输入、不同缓存和不同时段混在一起，不能把账单差额解释成 Sparse 固有的同条件成本倍率；原 UNKNOWN 费用另不可知。


### Q007/Q028/Q045：防止错误归因的控制案例

- Q007 一斗“【生日】6月1日”：原始 BM25F 双粒度均1，Dense窗口无同ID，Sparse macro7/micro13；S2 同时将 BM25F 权重减半，召回1→14，但 BGE两边均1，生日证据保住并入包。两份实际答案都为荒泷一斗。
  S2 经原操作恢复后做独立最终综合，原失败 turn 保留，不当作完整无故障的常规配对；S0 还主动补查派蒙生日前提，调用数和行为差异不能归因于 Sparse。
- Q028 Sparse 的长版乌帽子 NPC 对话重复已有“**大日御舆是贤人·阿布拉克设计的建筑**”。它补上下文，不是新发现建筑者；相同196K全回读诊断从20片段变13片段，不能按身份增长认定收益。
- Q045 原始 Sparse 独有30个候选身份，最终 S2 前100中没有任何一个；相对 S0 的19个新增候选来自既有通道窗口内的排序/准入变化。因此不能把本题的候选变化当作 Sparse 独有发现。

S2 同时加入 Sparse 并将 BM25F .5→.25，不能用一个总差异自动隔离两者的因果贡献。
本轮通过固定窗口身份、各通道原始名次、同配对 BGE 分数、最终处置和原文做分层归因，没有运行新的未批准权重消融。

## 交付、限制与下一步建议

- 核心工程、9项 G6 夹具/163项相关检查、真实 S2 本地链通过；有限 Live 覆盖有一题常规配对、一题恢复综合，以及一题固定 Packet 诊断。
  本地 RAM 中断、传输 UNKNOWN 和单题样本限制均保留；不宣称完整 G7 产品验收。
- 独立审计断网重放 raw/SSE、usage、attempt/seal、源读回、Packet/引用、终态历史和预算；摘要见[审计](../../data/generation/g6-final-review-20261117-r2/audit.json)。
- **建议维持 S0 默认，把 Sparse/S2 保留为待研究能力。** 有用增量确实存在，但当前链没有稳定利用它，且 Q046 丢失了 S0 原本能交付的关键身份依据。
- 值得下一轮小范围研究“**S0 结果不变＋Sparse 独有候选补充**”，优先用 Q046/Q050 的已核验原文检查重复、入包机会和预算挤占；这不是本轮已经实施或冻结的新工作点。
- **暂不建议先上 DeepSeek 按需选择 Sparse。** 先解决“已有有效候选为何没进入最终 Packet”的问题，再评估模型是否能识别需要 Sparse 的真实缺口；检索路线选择本身不能解决组包和选择损失。

实现、配置和文档保留在工作区供审阅；无默认采用、提交或推送。密钥按用户要求保存在 Git 忽略的 `.local/deepseek/`，使用 Windows 当前用户 DPAPI 加密，未进入代码、报告或模型请求存档。
