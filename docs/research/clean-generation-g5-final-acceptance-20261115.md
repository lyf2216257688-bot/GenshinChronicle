## 本轮实施

- 正式渠道仍是 DeepSeek official / `deepseek-flash`，运行时读取 `DEEPSEEK_API_KEY`。
  配置升级为 `gc-g5-official-3`，角色上限仍为4K/8K/16K/32K，推理包含在输出额度内。
- `clean_chat` 为新 G5 显式开启参数错误反馈。完整终态、模型、usage、工具 envelope、
  已知工具/唯一 ID 仍必须合格；多余字段、缺参、类型/枚举/长度或参数 JSON 错误
  均拒绝执行，给出字段路径和明确原因。没有剥离字段、自动改类型或接受非法参数。
- 原生历史中的拒绝参数必须有精确关联的错误回执。整个含错误的工具批次不执行，
  合法同行动作收到 batch_not_executed；下一次模型请求重新规划/提交并全量校验。
  每 turn 最多两次纠正机会，均是同一 campaign 的新正常操作，计入全部硬上限。
  UNKNOWN、身份/usage/流终态、实际来源 hash/lineage 和账本异常仍停止。
- 模型把 fragment_id 填进 handle 等已发现目录中的字段值误用，也在 IO 前明确拒绝。
  可反馈已验证目录中的对应 handle 作为提示，必须由模型重新提交；程序不代改、不读取猜测来源。
- 当前 E 编号继续按精确 receipt/fragment 绑定，未按列表位置分配。已有独立 analysis 边界去重保留。
  新增反馈仅在“同一 fragment 身份＋完全相同正文 digest 已在当前任务可见”时引用旧正文；
  完整输出另存 immutable tool unit，既有 native history/reasoning/tool 消息均不修改。
  其他来源的同文、不同正文、未在当前任务交付的内容均不据此省略。
- 回答约束明确：没有找到证据不等于已经证伪，“许多年”不等于永远，未知叙事归属不强配人物。
- 已结束且调用全部封存的有限 campaign 可追加一次 code-only permit revision。
  它绑定原 permit 与已封存调用，严格禁止变更任何额度、到期时间、渠道和 settings；
  不能重开关闭的批次或迁移不兼容的在途 checkpoint。旧 permit/调用/账务保留原样。

### 工具自纠错：实现通过，真实闭环未证实

追问中明确标注一次额外字段注入，要求先提交带 fragment_id 的 read_source，再按拒绝反馈改正。
原始 API 响应显示：**模型在发送前就省掉了额外字段，两次均是合法参数**。
不能把这种预先规范化写成“收到工具错误后纠正”。本轮真实 tool_error_rounds 为0，
也没有 tool_argument_errors 响应。自然发生的首根字段值混用，在修复前已停止。

缺参/类型/多余字段、fragment/handle 混用、整批不执行、重新校验、次数耗尽、
错误回执中断后的零重复恢复均有离线证据；不把它们冒充真实模型能力。
已用真实封存错误及准确拒绝回执准备 `-c/next-validation/` 输入预览，避免未来再依赖
模型自愿制造错误。它保留原 reasoning 和来源绑定，**dispatch_authorized=false，未建新 permit、
未付费**；不会自动执行或借此重发 UNKNOWN。
