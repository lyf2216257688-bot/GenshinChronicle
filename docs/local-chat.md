# 使用 GC 本地聊天

在项目根目录双击 **Start-GC-Chat.cmd**。启动器使用项目已有的 Generation Python 环境和随源码交付的页面，在默认浏览器中打开 `http://127.0.0.1:17861/`。重复双击会复用同版本实例。更新后如看到后台版本不一致，请在原服务窗口按 **Ctrl+C**，重新双击启动器并刷新聊天页。

## 开始和接续讨论

1. 首次使用可点 **体验离线演示**。演示使用小型合成资料，适合熟悉发送、追问、查看原文和反馈的操作。
2. 讨论实际剧情时点 **新建对话** 或首页的 **开始真实对话**。打开 **开启问答批次**，在 **真实问答配置** 填入 DeepSeek 官方地址（可直接用 `https://api.deepseek.com`）和 API Key，点 **保存配置**。接着确认请求上限、时长和费用授权，再点 **开启批次**。批次面板会列出缺少的本地资产。[模型、索引与运行环境](rag-workbench.md#运行前提)
3. 输入问题，按 Enter 发送，Shift + Enter 换行。可直接追问“这个判断依据是什么？”。要让一个条件在后续轮次保持有效，勾选 **补充条件**。要撤回原来的说法，在那条消息下点 **纠正这条** 或 **纠正回答**，选择剧情前提或讨论范围，再提交修订。历史中仍能看到双方原话。
4. 第二天再次双击启动器，从侧栏打开原会话。草稿自动保存。若旧批次到期，开一个新批次，在同一会话发送下一条即可。可以在不同会话之间切换，或在顶部为会话改名。

窗口较窄时，从顶部菜单打开会话导航。点击引用后，原文在右侧详情抽屉中展示。可用抽屉的关闭按钮或按 Escape 返回对话。

在最近会话中，点会话右侧的垃圾桶并确认删除。该会话及关联反馈会从应用中移除，底层执行与审计文件保留。删除当前会话后会切到另一条会话，列表为空时返回首页。若该会话正在处理问题，请先停止并等状态结束。

### 批次、停止和恢复

- 保存 API 配置只写入本机。API Key 由当前 Windows 账号加密，页面重开时只显示保存状态。已有 `DEEPSEEK_API_KEY` 环境变量仍可使用，页面保存的 Key 优先。更换或移除 Key 前先关闭当前可用的真实批次。
- 真实问答沿用 G5 官方模型接线。每批可选 **2–10 次模型请求，有效 1–120 分钟**。同模式下的所有会话共享同一个开放批次。一轮可能包含多次查证和生成请求。面板显示已占请求数、已知 Token、批次上限和用量未知的次数。
- 已提交的轮次继续在本机服务中运行。刷新、切换会话、重新打开页面都从已保存的进度接续显示。要停止点击 **停止本轮**。关闭整个批次会停止该批次未结束的轮次，已发出的请求保留实际结果和占额。
- 要退出整个应用，在启动服务的控制台按 **Ctrl+C**。重开后，仍可继续且原许可有效的轮次显示 **继续本轮**。只有点此按钮才按原操作与原检查点继续。远端结果未知时，原操作保留占额，界面显示 **远端结果未知**。新批次可用于同一会话的新问题。

### 引用和反馈

点回答中的 **E01** 等引用按钮，打开本轮证据、父级原文、可用的说话者或条件及来源定位。不同轮次都可以有 E01，按钮始终指定本轮及其证据包。**查证过程** 展示检索问题、阅读次数和资料取舍。部分完成的轮次可以有正式答案，未发布的流式文字单独标为草稿。

点回答下的 **反馈** 或来源面板中的 **反馈此引用**，选择回答错误、证据遗漏或引用问题并填写说明。在侧栏 **反馈记录** 中可回到原回答版本及所指引文。没有绑定编号时，回答会说明缺少可打开的引用。来源校验失败时可直接针对这处引用反馈。即使能读到原句，仍需结合语境判断它能否支持回答。

## 本机数据

默认目录为 `data/generation/personal-chat-v1/`，首次启动时创建。「批次设置」会显示实际使用的目录。备份时先退出服务，再复制整个目录，其中包含 API 配置、会话、草稿、原文回执、回答版本、反馈、批次许可和调用记录。恢复到原路径可以保留运行许可与检查点中的绝对路径绑定。换 Windows 账号或电脑后应重新填写 Key。浏览器仅负责记住上次打开的会话和暂存尚未提交到本机服务的草稿编辑。共享语料、索引、模型权重和历史工作台按原数据绑定引用。[数据目录](../data/README.md)

端口冲突时，可在项目根目录用 PowerShell 启动其他端口。指定自定义数据根时选空目录或此前由此程序创建的产品目录。

```powershell
.\Start-GC-Chat.cmd --port 17862
.\Start-GC-Chat.cmd --root (Join-Path $env:LOCALAPPDATA 'GenshinChronicle\Chat')
```

## 开发与验收

`src/genshin_corpus/local_chat/contract.py` 定义产品接口和校验模型。运行时接口说明位于 `/api/v1/openapi.json`。前端开发使用 Node.js 24 及项目锁定的 npm 依赖。修改契约后，在仓库根目录用 PowerShell 重新生成类型并构建页面。

```powershell
$env:PYTHONPATH = 'src'
$py = '.\.local\runtime-py314\generation\Scripts\python.exe'
& $py -B -m genshin_corpus.local_chat.contract
Push-Location frontend
npm ci
npm run types
npm test
npm run build
Pop-Location
```

后端产品测试和浏览器测试在 `.local/tmp/` 下使用独立的临时目录与小型夹具。可选的官方接线测试用本机已有协议证明开启临时许可，使用内存传输，并在测试内禁止外部套接字连接。浏览器测试需要本机 Microsoft Edge，自动选择空闲端口并重启独立测试服务。

```powershell
$env:PYTHONPATH = 'src'
$env:GC_TEST_LOCAL_PROFILE = '1'
& .\.local\runtime-py314\generation\Scripts\python.exe -B -m unittest discover -s tests/local_chat -v
Push-Location frontend
npm run test:browser
Pop-Location
```

前端的 `src/api/` 负责传输和类型，`src/chat/actions.ts` 负责可注入客户端的聊天操作，`src/chat/state.ts` 负责会话、草稿、进度和面板状态。界面呈现位于 `src/components/`、`src/App.vue` 和 `src/styles.css`，地脉和星图相关视觉资源随前端本地构建。
