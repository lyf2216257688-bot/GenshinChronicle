# BGE-M3 Sparse 全量构建合同 V1

2026-11-12。当前授权由 [current-phase](../current-phase.md) 管理。本工作单元只实施
P3 工程准备和短测试；119,557 条全量编码由用户在独立 PowerShell 执行。
P4/P5、70题、Serving、付费 API、Commit/Push 不在本轮范围。

## 输入、表示与存储

固定复用 `config/index-selected-v1.json` 的共享输入包、BGE-M3 主干和 Sparse head。
不重新导出 Clean/Chunk，不重建或覆盖 Dense/BM25F。文档使用完整原 `dense_text`，
不截断、不剪枝、不增加 IDF/L2/量化。Sparse 数值合同复用 P0–P2 的独立 space_id；
宏微是同一物理 Chunk 的两种成员资格，不重复编码，也不解释为父子关系。

`indexing/sparse_full.py` 复用 SciPy CSR/NPZ、原编码器、来源映射及事务回执。
只常驻一个分片的原文/向量/矩阵和轻量身份、定位或回执表；查询逐片精确点积，
分别维护宏微 TopK，先按成员资格过滤再入堆。正分才入选，并列按 input_row。
不会把全库 CSR 拼接或常驻，也不新增数据库或服务。它提供独立 Sparse 搜索原语，
不接入 S1/S2 的实际在线 Runtime，不改变 S0 或重排/生成边界。

计划绑定输入及源文件哈希、模型/Tokenizer/head/包版本、实现哈希、分片布局和范围。
每片包含 `weights.npz`、`rows.jsonl` 和最后发布的 `complete.json`；回执包含哈希、
起始位置、行数、宏微数量、nnz、空向量数量和执行批次设置。
两路 representation_id 同时绑定输入包、Sparse 空间、范围和粒度。
全量输入必须按 input_row 连续覆盖，Chunk 身份不重复，宏微数量与原输入完全相同。
空向量记账，不视作丢失行，不用零分结果填满 TopK。

## 独立入口

`scripts/retrieval/run-sparse-build.ps1` 使用配置中的既有 candidate-runtime。
五种模式：

| 模式 | 行为 |
| --- | --- |
| Preflight | 全量只读来源/成员/长度审计绑定；只编码32条结构样本及少量工程查询；官方核、P0–P2、查询点积和恢复检查；发布预检报告和计划 |
| Run | 必须已有通过的预检，输出不得已有构建分片；用户显式执行才开始全量编码 |
| Resume | 核对相同计划、代码、输入和模型；验证并复用已提交分片；不重算其编码 |
| Status | 只读显示进度、预检/校验指针和最后事件；不占构建锁，不运行推理 |
| Validate | 独立流式校验全部文件、矩阵和逐行源映射；抽取16条回读 Chunk/Parent/Graph/Clean/自然父层；不加载 GPU 模型或重编码 |

具体命令及操作见 [P3 运行说明](../research/sparse-build-preparation-20261112.md)。
Preflight **不会自动转入 Run**；Run 不会自动运行 Preflight。
一次启动由独立系统终端直接拥有 Python，不依赖 Codex 会话，不启后台监控。
运行期间抑制 Windows 空闲睡眠；仍需防止手动休眠、关机和终端关闭。

## 恢复和资源

输出根采用系统排他锁；锁文件保留，进程死亡后由系统释放锁，不能靠删除锁抢占。
没有回执的尝试目录保留并忽略；重试创建新目录，不覆盖半成品。
完整回执出现但哈希损坏时失败，不自动删除、覆盖或偷偷重算。
Ctrl+C、关终端或异常中止后使用同 Output 的 Resume；最坏重算当前未提交的一片。
`manifest.json` 只在全部覆盖和独立存储检查、最终源/代码绑定检查后发布。
完整存储清单与随后独立 Validate 报告是两种证据，不等于质量选型或采用。

启动和批间检查系统 RAM、磁盘；模型加载前检查 CUDA 可用及空闲显存。
CUDA OOM 仅对当前批减半重试，单条 OOM 明确失败；不转 CPU、不截断、不跳行。
系统内存或磁盘不足明确失败，释放资源后续跑。`MemoryError` 等其他错误不自动循环重试。
进度事件包含 UTC、PID、系统 RAM、进程 RSS、已初始化 CUDA 的分配/保留峰值和空闲量。
每片开始/提交/复用、约15秒批心跳、OOM、失败和完成写入 `events.jsonl`；
`progress.json` 原子更新已提交行数，`runs/` 中每次运行独立保存 stdout/stderr 和结果/错误。
强制结束可能没有最后一条错误记录，恢复以已验证回执为准。

配置中的 shard_rows=256、max_batch=1、padded_token_budget=2048 是保守起点；
119,557 条对应468片。它们不是永久算法约束。批上限可用 `-MaxBatch` 显式调整，
执行设置写日志和回执；分片大小在同一计划内保持不变，改布局必须使用新输出和预检。
确定性指身份、顺序、覆盖和固定执行设置下的确定性内核；FP16 改变批次组合可能有
有限舍入差异，已有片保持原字节。预检按0.005有限数值容差核对，不声称不同批配置逐位一致。

资源保护起点：启动可用 RAM 2GiB，加载后/写片前0.75GiB，磁盘余量6GiB，
加载前空闲显存1.5GiB。实际首批还要在 Torch/Tokenizer 准备后通过启动 RAM 门槛，
因此建议运行前留出至少3GiB系统可用内存。配置可审慎调整，不以降保护掩盖资源不足。
本阶段不承诺可靠全量 ETA；32条结构样本不能代表全库吞吐或 nnz 分布。

## 验收和反向检查

小夹具覆盖精确分数、并列、共享/单路/空向量、内存分片、错空间、源覆盖、绑定漂移、
磁盘/RAM保护、OOM减批、单条OOM、半写、损坏回执、真实子进程强杀及系统锁恢复。
真实预检覆盖最长1,135-token输入、双路/专属、对白、条件和特殊Token；
数值核对 P0–P2 产物和固定官方 Sparse 核，不宣称完整 FlagEmbedding 流水线一致。
实际原文及完整定位保留用于人工直观核对，不做质量胜出判断。
完成后由用户另行委托验收；代码不会触发70题或自动切换 Serving。
