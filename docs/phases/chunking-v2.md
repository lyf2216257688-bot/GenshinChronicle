## 1. 输入、版本和运行范围

输入为完整Clean V1清单及显式选择文件。Raw/Clean为只读来源，Chunk是可重建派生层。
本轮选择文件为[chunking-pilot-v2.json](../../config/chunking-pilot-v2.json)。
输出、候选及报告版本为`gc-chunking-pilot-2`，准入版本为`gc-story-admission-pilot-3`。
旧选择文件的字段形状仍可读取，当前构建代码输出V2。重建使用新输出目录。

结构感知、微观与宏观独立构建、自然父层、CleanRef和精确语音出现别名继续使用。
balanced保持微观240/384、宏观720/1024 Qwen Token，BGE文档上限1792 Token。
全部检索可见标题、条件及派生标记计入预算。实现使用本地Tokenizer。

默认12个独立记录Worker，动态调度、逐记录锁、原子凭据和确定性汇总沿用既有构建机制。
`--workers 1`执行同一规则，`--resume`验证绑定与文件哈希后复用已完成记录。
规则或代码变化后建立新运行，完成清单最后发布。

## 2. 准入及回读

- 源类型为null的值进入`source_null_placeholder`上下文处置，普通文字中的字面null及未知数字继续保留。
- 对白结构控制字段、筛选器`/options`和`/table/filter`进入上下文。
- 洞天`cave_base_info:/rate`排除正文。卡牌生命、费用、充能及技能类型控制值转为上下文。
- 卡牌明确标为技能效果、天赋效果或召唤物效果等的值排除，未知描述与卡牌故事保留。
- 表格依据原列名和用途处理。明确机制列排除，纯机制表剩余行名转为上下文。
  相性表还要求观察到的用途标题及列组合。OST时长列规则限定在OST栏目。
  描述、文案、场景对应、未知所属及故事表中的时长、材料等继续保留。
- 机械模块标题作为风险提示。通用正文保留并记为`mixed_or_uncertain`。
  奖励/商店作用域中的完整物品乘数量格式，以及独立版本号字段可局部排除。
- 混合天赋desc、世界观与机制无法可靠分开的正文整体保留。长度、斜体和文学关键词不单独决定准入。
- 非成就描述与标题仅有首尾空白差异时转为上下文。完整短知识继续保留。
- 成就简单解谜折叠、文章格式边界、千星奇域及洞天机制字段规则继续生效。

每个源值保留准入处置与理由。`read_natural_parent`继续返回完整源容器。
默认检索文本从准入后的父层`units`构造，完整父层用于明确要求的来源回读。

## 3. 对白图、条件及顺序

`graphs.jsonl`的`group`完整保存原节点、原边、声明根及源顺序。
`derived_nodes`另存可达性、弱连通区域、入/出边、局部分支、条件及来源引用。
`display_order`为拓扑展示序，`source_order`为源数组位置。
候选新增`display_order_by_granularity`，分别保存两路展示序号。
兼容字段`order`沿用首先生成该候选时的序号。编号的语义为`display_only`。
事件时间、因果和剧情时间线需要独立原文证据。

普通选项以实际源边和观察到的旅行者/括号选项格式识别。
正文显示选择点、并列选项与公共后续，单次选择使用“本次选择择一”标记。
局部分支标记沿边传播，嵌套汇合保留共同外层标记。一般源图分叉显示关系待解释。
独立检索片段继承源图分支提示，分支切换时重新显示，避免提示仅存在于起始节点。
同一源节点的公共后续在每种粒度只保留一次主正文。不同源出现保持独立身份。

源条件覆盖完成前后、任务期间、选项尾部、历史选择、首次/再次接取及昼夜格式。
`condition_sources`保存完整原文、CleanRef、直接/继承依据与识别状态。
复合条件原文整体保存，使用`unresolved_literal`标注其解释状态。
源动作注记与条件分开，独立括号注记保留来源。对白中的普通“如果”句保持正文身份。

| condition_status | 解释 |
| --- | --- |
| source_marked | 已识别有源依据的条件标注 |
| not_established | 当前未建立条件标注 |
| unresolved | 条件注记或连接存在未解释之处，已知原文仍保留 |

沿实际连接继承条件，多前驱取共同继承部分，另存每个入边的条件来源。
空交集保留汇合来源信息。未知状态可沿原连接传播，避免遗漏上游不确定性。
每个节点的空条件集也参与合并与尾块回并比较。不同条件或源连通区域保持边界。
有环组只保留直接条件并降级为局部节点表示，全部源边继续保存。

长节点续片保留源节点、片内原范围及条件，显示“节点内续片”。
短选项和实际唯一前驱的完整短段/句子可成为来源语境，均附CleanRef。
可选上下文超预算时记`optional_context_deferred`，引用继续保留。
必需条件或标题超出最小可用预算时明确失败。

任务前置、后续、触发条件和起止NPC仅从明确字段转交，保存源链接与目标ID。
相邻模块和布局位置属于展示元数据，其关系语义由原来源承担。

## 4. 检索字段职责

| 字段 | 责任 |
| --- | --- |
| body_text、parts.text | 可引用原文，承担语义检索主体 |
| context_text、context_sources | 必要标题、提问、适用条件及文章标题，引用型上下文附CleanRef |
| parts.display_prefix | 有源结构依据的派生关系标记 |
| retrieval_text | 正文、必要来源语境及可读分支标记的推荐投影 |
| 编号、源ID、图边、哈希、CleanRef、覆盖关系 | 定位、过滤、关联、回读及组包控制 |

检索投影保留语义限定，内部ID、哈希及完整图JSON留在结构侧。
索引拥有字段投影和权重，召回拥有双路融合及关系扩展，重排拥有相关性与互补性排序。
生成拥有预算内回读、条件解释、证据组包、联读及引用。来源性质和未知状态持续保留。

## 5. 不可达节点与验证

`python -m genshin_corpus.chunking.audit_unreachable`读取已完成Chunk清单中的图侧文件，
校验图文件及Clean清单哈希，输出逐节点`nodes.jsonl`及完成manifest。
此入口执行图分类，输出目录须位于下游数据区。

分类依据声明根及现存有效边，区分缺根、有效根组中的孤立节点及其他不可达连接区域。
交叉记录空文本和与可达节点完全同文的情况。每行含观测、模块、组、节点、原边、origin及字段CleanRef。
同文标记保留各自源身份，分类事实不补充缺失剧情连接。

构建检查覆盖逐粒度准入范围、别名、条件、来源语境、标题、任务关联及两路展示序号。
回归使用小型fixture，真实试点使用批准的35份资料。串行、12路和实际中断恢复比较完整产物。
有限结果、实际样例、7,759节点分类及剩余噪声由[V2试点报告](../research/clean-chunking-v2-20261107.md)负责。
全量重建、索引采用及回答收益分别经过后续审议。
