# Clean 双粒度分片试点 V1

2026-11-07用户授权实现和运行有限真实资料试点。当前工作状态由
[current-phase](../current-phase.md)维护，初次结果见[历史试点报告](../research/clean-chunking-pilot-20261107.md)。
本文是可修订的试点接口与工程设计。用户随后确定双粒度并行检索、balanced默认配置，
compact保留为历史实验资料。双路融合和生产采用由相应后续工作单决定。
三类结构规则的后续修改见[定向优化报告](../research/clean-chunking-refinement-20261107.md)。

## 1. 输入、职责与运行范围

输入为完整 Clean V1 manifest 中显式选择的记录。构建入口核对清单完整状态、
选择集合、记录哈希、身份及 source/locale/Raw run，并复用 Clean 的版本校验。
普通分片仅使用结构规则和本地 Tokenizer。

初次试点选择配置在[chunking-pilot-v1.json](../../config/chunking-pilot-v1.json)，
包含51条资料，当前只启用balanced。原选择集合来自Clean组件试点、全量调查案例及森林书其余三章。
后续三类优化使用[12条定向选择](../../data/retrieval/clean-chunking-refinement-20261107-review/selection.json)，
单次处理范围以工作单授权和显式选择文件为准。新的试点使用新输出目录，已存在的目录会被拒绝覆盖。

`genshin_corpus.chunking` 提供独立入口，产物写到 `data/retrieval/` 下。
Raw/Clean 作为只读输入，输出目录检查阻止写进选定 Clean run 和名为 Raw/Clean 的目录树。
运行后再次核对选定记录及 Clean manifest 哈希。

## 2. 内容准入

准入规则与分片组织分别实现。`policy.py` 拥有版本化的组件、模块、字段用途规则。

- 保留普通故事、书卷、图对白、物品描述、教程背景、考据及千星奇域文字。
- 对角色突破、装备成长、推荐配装、攻略组件等明确机制结构进行排除。
- 依据原字段标签排除攻击力、价格、库存、培养数量等字段，排除天赋的数值表。
- 混合天赋 desc 整体保留。边界不明的普通文字按保守规则纳入。
- 源富文本中明写的“达成奖励”“上线版本”“使用效果”字段前缀用于局部排除，
  规则只识别字段标记，不对故事句子做文学关键词分类。
- 字段标签匹配去除首尾空白及末尾中英文冒号。洞天的摆设/图纸获取途径、洞天仙力、
  摆放区域及分类等字段按组件和栏目作用域排除，制作工艺和历史正文保留。
- 千星奇域`material_base_info`的部件数量、适用性别、色系、部件/色系排除。
  “特殊”字段仅在值精确等于“激活套装效果必须部件”或“部件可调整”时排除，混合值保留。
- 成就`collapse_panel`中，`details/summary`明确标为解谜流程、步骤或攻略的简单折叠区排除。
  兼容已观察到的“· 解谜流程可以点击此处折叠栏查看”。含嵌套标题或折叠区时整区保守保留。
  通用“补充说明”、折叠区外正文及用途不明的折叠标题继续保留。
- 标题、分组名、字段名、表头、标签和来源信息作为上下文保留。
  音频文件名、资源地址和控制 ID 留在回读资料和准入账中。用途不明的独立标量保守保留。
- 源 `option` 的完成条件及其台词保留，条件原文用于显示局部作用范围。
- `provenance.state=unknown` 原样携带。考据栏目与可见作者信息保留其证据身份。

每个读取到的 TextValue 都有纳入、排除、上下文、空值或待查处置。
无法解释的非空 opaque 留下待查项，空组件留下资源处置。
这些处置只影响派生表示，完整自然源容器通过 Clean 回读。

当前准入版本为`gc-story-admission-pilot-2`。缺少可靠子结构的解谜操作仍可能保守纳入。
明确解谜标签提供编辑用途依据，未单独标记的内嵌背景仍有误排风险。
组件目录、标签和字段不能提供全文的语义判决。

## 3. 两个输入适配与一套核心

### 3.1 结构文本适配

利用模块、有名条目、局部标题及表格形成自然父层。无名外层容器可以让其相邻短段进入同一父层。
每个有名条目、书卷和模块分别处理。字段值带原标签，字段标签与正文分开存储。

普通富文本对白沿原段落处理，书籍中的舞台对白也走此入口。
HTML 标题形成局部父层并记录其兄弟块范围。
正文数组维持源顺序，模块额外携带布局观察供后续排序或回读。
本试点跨模块关系仅保存在布局元数据中。

表格行是优先保护的单位。列标题、行标题、逻辑列和原 span 随片段保留。
JSON 表头与 HTML `th` 各有恢复规则。行超长时拆到段落，继续附带行标题和列标签。
复杂嵌套、跨行列跨度的完整关系通过原表格父层回读。

语音按源语言组和命名条目组织。仅当同一观测内的语音条目名、逐段文本完全一致时，
合用一份候选文本，保留所有出现的自然父层和 `alias_clean_refs`。
别名范围逐项对回 Clean，原语言、音频及条目结构均可回读。

### 3.2 图对白适配

直接使用源根、边及节点，生成稳定的拓扑显示顺序。根和有序边遍历提供同优先级顺序，
汇合节点等待全部前驱，公共后续的主正文出现一次。
每个节点显示派生编号及后继编号，完整源 ID、全部边和原数组顺序在图侧文件保留。
`option` 在显示时放在该节点 `dialogue` 前，字段的原定位持续保留。

具有选项且只有一个前驱时，可携带前驱末尾完整短段作为“上接原文”。
这段上下文另带 CleanRef，仅在当前片段未包含对应正文时显示。
长于 140 Unicode 码点的上接段留给源连接和父层回读。

明确写有完成/未完成和触发等表述的源条件沿连接传播。
多前驱处取共同继承的条件，避免把单一分支的条件覆盖到共同后续。
不同显式条件作用域之间保持片段边界，尾块回并同样遵守该边界。
这是一项保守的源结构显示规则，条件复杂逻辑和全局任务状态仍通过原图解释。
缺根、孤立、悬空和环都有显式状态，全部实际节点仍保留。
源缺少可靠 speaker 时保留 `null`，文字称谓继续留在原文。

图节点优先整组保护。超过长度预算时才拆到节点字段和段落，源节点身份、条件、连接始终保留。
有源标题的节点开启新的局部单元，超长节点内部的源标题继续提供拆分边界。
此类节点从自身标题开始表示，上接文本留给连接回读。
整条剧情路径不展开枚举。

同一HTML容器中出现至少两个完整居中、整段符合书名号标题格式的段落时，
将其识别为文章起点。源节点内部先按文章作用域形成单位，两种粒度及短尾回并均遵守边界。
真实HTML标题结束此前文章作用域。单个居中标题、正文中的书名号及缺少格式证据的文字继续沿普通结构处理。
分片保存`article_scope_ids`，对应原始节点的`local_scope_ids`继续保留。
续片附带有CleanRef的源文章标题，完整原图和自然父层保持可回读。

### 3.3 通用核心

适配器输出 `parent -> ordered units -> source parts`。
核心分别从这些原始单位构造微观、宏观候选。宏观构建直接读取原始单位。

1. 自然父层之间保持边界。
2. 父层内相邻短单位按序组合，达到软目标后优先收束。
3. 在硬上限允许时接回很短的尾块。
4. 超长单位按已有子段落继续拆，超长段落按中文句末边界拆，最后使用原文字符范围兜底。
5. 每次组合均计入源标题上下文、源连接标记及上接原文的真实 Token 数。

当前无固定滑动重叠。跨片段联系由上下文、相邻顺序、覆盖关系与完整父层提供。
任何被句末或字符范围切开的原文都有完整字符区间，覆盖检查按两种粒度分别进行。

## 4. 双粒度与长度操作点

| 候选配置 | 微观软目标 / 硬上限 | 宏观软目标 / 硬上限 |
| --- | --- | --- |
| balanced | 240 / 384 | 720 / 1,024 |

计量单位为本地 Qwen Tokenizer 的 Token，包含 special token 和完整检索表示。
另设 BGE 文档 1,792 Token 保护上限，并测量真实问题与候选文本的分词对。
balanced为用户确定的默认分片配置，本轮结构优化保持以上数值。
compact的160/256与480/768及其产物保留在[初次试点历史报告](../research/clean-chunking-pilot-20261107.md)。

短条目若微观与宏观覆盖完全相同，仅生成一条带 `granularities=[micro,macro]` 的候选，
两种索引路线均可选择它。其他候选分别具有独立 ID 和检索文本。
微观块可以跨宏观块边界，两者通过 CleanRef 范围交集建立 `overlapping_chunk_ids`。
因此，片段覆盖关系支持多对多，`parent_id` 始终表示自然父层。
`local_scope_ids` 进一步指向源节点或表格行，便于后续按局部覆盖分组，避免整段长任务只剩一个配额。

自然父层保存完整来源回读能力，尺寸可以很大。完整父层是否向量化、检索路由和融合、
局部父层配额、MMR、最终证据组包与上下文预算，分别留给后续索引、召回、重排和生成工作。

## 5. 产物接口

| 文件 | 主要内容 |
| --- | --- |
| `manifest.json` | 完成状态、Clean 和代码哈希、选择集合、Tokenizer 哈希、产物哈希 |
| `parents.jsonl` | 自然父层身份、层级、源容器、原文单位、布局、完整来源回读入口 |
| `graphs.jsonl` | 原始对话组、节点、边、根、显示顺序和结构问题 |
| `admission.jsonl` | 每个源值的处置、规则理由、原字段与 CleanRef |
| `chunks-balanced.jsonl` | 独立候选、粒度、原文、上下文、引用、覆盖关系和实测长度 |
| `report.json` | 有限试点统计与范围核对 |
| `review.md` / `review.json` | 实际候选的完整可读文本及机器引用 |

片段 `body_text` 是源片段按换行组合的正文，`retrieval_text` 包含显式的派生上下文和连接显示。
`parts[].clean_ref` 对应单段实际源文，`alias_clean_refs` 保存精确语音复用出现，
`upstream_context`独立标明上接原文及引用。`article_title`保存续片标题引用，
`article_boundary_evidence`保存实际居中格式证据。标题、条件显示前缀都有原文或结构依据。
`context` 携带栏目、标签、布局、原出处状态和标题证据。

`adapt_record`、`chunk_parent` 及 `read_natural_parent` 可直接调用。
`read_natural_parent(parent, record)` 读取原始完整源容器，包含准入时排除的字段。
结构标记与源证据分离，字符范围沿用 Clean 的 Unicode 码点口径。

## 6. 运行和检查

以下命令在项目根目录的 PowerShell 7 运行，复用已安装的本地分词环境。
输出目录必须尚未存在。

```powershell
$env:PYTHONPATH = 'src'
$env:PYTHONIOENCODING = 'utf-8'
.\.local\embedding-runtime\Scripts\python.exe -m genshin_corpus.chunking `
  --clean-manifest data/clean/mihoyo_obc/zh-cn/clean-v1-full-20261106/metadata/manifest.json `
  --selection data/retrieval/clean-chunking-refinement-20261107-review/selection.json `
  --qwen-tokenizer .local/models/qwen3-embedding-0.6b/97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3/tokenizer.json `
  --bge-tokenizer .local/models/bge-reranker-v2-m3/953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e/tokenizer.json `
  --output data/retrieval/clean-chunking-pilot-new-run
```

实现复用已有 Clean 版本和来源解析接口，核心本身只依赖标准库。
CLI 的 Tokenizer 来自既有本地环境。试点目录缺少完成 manifest 时按未完成处理。
有限运行失败后保留部分目录，使用新目录复跑。

自动检查覆盖每种粒度的全部准入字符范围、所有片段/别名/上接原文/文章标题引用、
候选 Token 硬上限、自然父层可回读性和输入前后哈希。
小型源 fixture 回归覆盖条件、汇合、表头、Unicode 拆长和字段准入。
这些检查建立工程与来源一致性，实际召回和答案质量由后续实验判断。
