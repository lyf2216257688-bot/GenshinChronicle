最初的准备工作单元中，Codex只准备代码、短测试及独立命令；完整70题由用户在独立 PowerShell 手动启动。
本轮实际预检因可用内存不足停止后，用户进一步指定真实预检和单题短测也由其手动执行。
不重建索引、不调用付费 API、不切换 Serving、不改正式资产、不自动 Commit/Push。
后续操作者已完成实验；2026-11-13授权并完成保存结果的轻量逐题Top10/Top20审查，

## 固定证据与可变工作点

复用已选 BGE-M3 Dense、Whoosh3 BM25F 和通过独立 Validate 的完整 Sparse。
Sparse 只由独立实验配置引用，不修改正式 selection。共享 input_bundle_id、119,557
Chunk、104,879 micro/78,658 macro 成员；宏微不是互斥集合或父子树。
实际保留的70题为 `data/retrieval/index-benchmark-v1-70q-raw-20261110/question-set.jsonl`，
按字节哈希及 Q001–Q070 顺序绑定，只含问题，不把历史答案或盲审结论送入检索。

配置 `config/recall-experiment-v1.json` 独立拥有实验参数；初始两路深度50、输出100、
RRF k=60，观察10/30/100。S0/S1等权，S2 Dense=.5、BM25F=.25、Sparse=.25。
不将这些参数或 F1_max 作为永久约束。改参数/代码/输入/模型需使用新输出、重新预检，
不能在同一计划中混用结果。本轮不大规模调参。

## 执行与公平比较

每题原问题执行一次 Dense、一次 Sparse、一次 BM25F，分别获得宏微原始 TopK。
所有组合/融合复用这份命中，不重复检索。Dense/Sparse 在同一隔离进程共用既有主干，
进行两次单题前向；不为节省一次前向改造已验收编码算法。神经进程结束后才启动
BM25F 进程，两个词法粒度继续逐路打开 reader，避免叠加常驻内存。

主比较：S0/S1/S2 的 F1_max + 结构整理。有限控制：每组合的 F0、F1_rrf 和 F1_max
关闭结构整理，共12个廉价离线融合配置，不增加索引扫描/模型推理。
粒度内 Weighted RRF、跨粒度最佳贡献和保守包含延后复用 P0 实现；不做中间截断，
相同 Chunk 输出一次，保留所有通道/粒度命中。控制项用于发现 F1 或整理导致的候选
挤出/覆盖变化，不据此自动选算法，也不要求机械零损失。

## 自动诊断与原文

- 宏微各自及并集的 Chunk 重合、双向独有；集合按共享 Chunk 身份计算。
- Sparse/BM25F 互相独有后，继续检查 Dense 同 ID 覆盖及严格来源包含；深度外仍未知。
- 固定上限前排的 S0/S1/S2、F0/F1、整理开关双向名次/挤出/来源字符覆盖变化。
- 主正文来源范围并集、重叠字符、Parent/观测多样性、同 Parent 占位；不把字符覆盖
  或“未证实包含”当作有效证据。不同观测、条件、选项、别名不凭同文合并。
- 每题存一份完整原 Chunk/输入行，12配置只引用它；保留全部原始命中、排序及所有
  未入上限候选的处置。原文页显示真实 retrieval_text、条件状态、来源性质和 CleanRefs。
- 报告按预声明的 Sparse 独有、BM25F 独有、S0被挤出、F0/F1变化、整理变化和低差异
  控制选至多6题；所有70题的原文入口继续可用，不将精选案例当作质量比例。

有效剧情证据、独有收益和明显退化以少量原文抽查判断。不做正式盲审、复杂人工标注
或完整 nDCG，也不让未执行的判断显示为 PASS。最终组合由用户决定。

## 日志、恢复与校验

独立入口 `scripts/retrieval/run-recall-experiment.ps1`：Preflight / Smoke / Run / Resume /
Validate / Report / Status。Preflight 只读校验全部输入/索引哈希、独立Sparse验收绑定和
70题长度，不编码任何实验问题；Smoke 在单独根只跑1个独立工程问题，不使用70题。
只有用户显式 Run 才执行完整70题；Resume 根据已绑定计划恢复。
70题 Run/Resume 必须先有配置中 smoke_output 的同代码/配置/资产单题 Smoke，并通过
其独立 Validate；不允许将夹具测试或预检 PASS 当成真实模型短测。

计划绑定源码、配置、题目、输入/来源、模型/head/Tokenizer和三个索引实际文件。
系统排他锁复用既有实现。逐题/通道组写唯一尝试目录，result.json及必要产物先落盘，
complete.json最后发布；半写尝试保留且忽略，已提交损坏则停止，不删除/覆盖/静默重算。
神经组原子保存 Dense+Sparse；BM25F、逐题融合分别提交，中断最坏重跑当前未提交组。
Resume 不重算已有完整组，完整输出不会隐式运行新的检索。
各次 stdout/stderr、failure/result、worker准备及stderr完整写文件；events/progress提供
组/问题开始、提交、融合与失败进度。长单题期间可没有新事件，不能据此判断卡死。
Windows Job Object拥有子进程，异常或父进程关闭释放模型进程；无需手工删锁。

启动可用 RAM 2GiB、运行0.75GiB、空闲显存1.5GiB、磁盘6GiB为保护起点。
模型加载前还需在Torch/Tokenizer准备后通过启动RAM检查，建议关闭桌面软件后
留出至少4GiB系统可用内存。预检的Tokenizer/模型绑定检查在短命隔离进程完成，
协调进程不常驻Torch，避免与正式模型工作进程叠加。
单题 OOM/RAM不足明确失败，无截断、跳题、换模型/CPU或静默减少深度。释放资源后续跑。
默认单题编码，无法再减批；不升级隔离环境或调整正式配置掩盖资源不足。

完成后独立 Validate：检查每个回执/组/题/表示身份，逐命中核对输入行和原 Chunk，
离线重放12配置全部排名、结构处置与诊断；不再推理/检索。抽样父层/Clean/原图回读
另存每题结果，不扩大检索候选。Report 可重复生成新的报告，旧报告保留。
报告包括所有题的诊断JSON、名次/覆盖/成本TSV及少量完整原文页；不会改用选型或 Serving。

时间记录区分准备、编码、扫描、融合。通道相加是离线分量估计，不是实测在线端到端
延迟；固定通道顺序、缓存、首题加载影响必须随报告展示。资源峰值为对应进程的
可观测值，不把单个 RSS 快照称作系统峰值。70题是历史固定诊断集，不代表全库无偏质量。
